# PageNest（拾页） 核心阅读主流程差距与实施优先级

> 文档状态：`ACTIVE / P0、P1 实施与验收跟踪`  
> 最后静态核对：2026-08-02  
> 对照基线：同级兄弟仓库 `legado-with-MD3` 的原生 Android 实现  
> 关注范围：书源 → 搜索 → 详情/目录 → 加入书架 → 阅读 → 整书/单章换源  
> 本文只负责差距排序，不代表任何阶段已经通过构建、真机或正式验收。

## 1. 目标和排序原则

本文用于回答两个问题：

1. Flutter 当前核心阅读主流程与原生 Android 还差什么；
2. 下一步应先解决什么，才能最快提升真实可用性和阅读体验。

优先级按以下顺序判断：

1. 是否会让搜索、目录或正文完全不可用；
2. 是否可能破坏书架、阅读进度或换源后的数据；
3. 是否明显影响每天阅读时的稳定性、流畅度和正文质量；
4. 是否有可接受的临时绕行方式；
5. 是否只是高级外观、低频管理或非核心阅读功能。

因此，本文不会单纯按“缺失功能数量”排序。真实书源兼容、正文正确性和进度安全高于新增页面与视觉细节。

## 2. 状态口径

| 状态 | 含义 |
|---|---|
| `BLOCKED` | 已确认存在会阻断真实使用的技术或验收问题 |
| `IMPLEMENTED_PENDING_VERIFICATION` | 主要代码已存在，但没有足够真机结果，不能视为完成 |
| `PARTIAL` | 只有基础子集，与 Android 仍有明确能力差距 |
| `NOT_STARTED` | 主体能力尚未迁移 |
| `DEFERRED` | 保留在范围中，但不应影响当前核心主流程交付 |

项目文档曾记录 2026-07-16 进行过一轮 Android 主要逻辑冒烟，但当前 M4、M6、M8、M9 和 M11 的正式样本矩阵仍未关闭。因此本文统一使用“代码覆盖较高、正式可用性仍需收口”的判断，不把代码存在等同于完成。

## 3. 当前总体结论

Flutter 已经具备核心阅读闭环的大部分页面、状态机和数据链路：

- 书源导入、编辑、启停、分组、二维码和 WebView 登录入口；
- 多书源并发搜索、停止、失败重试、结果聚合；
- 详情、完整目录、加入书架；
- 正文加载、目录跳转、切章、分页、连续滚动、进度保存与恢复；
- 书签、正文搜索、替换规则展示、刷新当前/后续/全部章节；
- 整书换源、单章换源；
- 持久离线下载队列、跨书下载管理、Android 前台服务和 iOS 有限后台续传；
- 书架/阅读历史双页、游客与账号本地数据隔离、启动目录自动更新；
- 搜索或选择本地图片替换封面，并同步已有阅读历史快照；
- 网络正文图片、原生选区、书签、高亮和下划线；
- 首次阅读先导页、书架/历史封面转场、边缘滑动退出和处理后正文 LRU。

当前主要问题不是“主流程页面缺失”，而是以下三类差距：

1. **成功率差距**：真实普通规则和 JavaScript 书源尚未形成稳定兼容率结论；
2. **成熟度差距**：阅读、换源和离线下载已有代码，但真机稳定性和异常路径没有收口；
3. **体验差距**：正文内容处理、文本选择和用户标注代码已进入验证，TTS、自动翻页等 Android 高频能力尚未完整迁移。

## 5. P0：必须优先收口

统一的最终真机与真实书源验收记录见 [`P0_PENDING_VERIFICATION_CHECKLIST.md`](./P0_PENDING_VERIFICATION_CHECKLIST.md)。

### P0-01 真实书源兼容率收口

#### 当前已有

- 普通规则与 JavaScript 混合执行链已经接入搜索、详情、目录和正文；
- 标准 JavaScript、`jsLib`、书源 Scope、缓存、Cookie 和部分 Java 白名单已经存在；
- WebView 登录和 HTTP/WebView Cookie 同步边界已经接入；
- 未支持 API 会返回可诊断错误，不伪装为空结果。

#### 与 Android 的关键差距

1. Android Rhino 的 `java.ajax/connect/get/post` 是同步调用，Flutter 现以“等待 Future 后从头重放并同步复用宿主结果”兼容旧脚本；该方案尚缺 Android/iOS 真实书源验证，不能视为已通过。
2. `Packages.*`、`JavaImporter`、`JavaAdapter`、Android API 和任意 Java 反射不能完整等价迁移。
3. `java.createSymmetricCrypto` 等 AES/DES 能力尚未接入经过评估的跨平台实现。
4. Flutter 已按 Android 响应顺序执行 `loginCheckJs`；`java.startBrowser/startBrowserAwait/getVerificationCode` 由业务操作与交互策略统一拦截，默认返回 `interactionRequired`，不会在搜索中自动弹窗。用户显式开启设置后，交互申请进入应用级 FIFO 单消费者队列，逐个确认并打开可见登录、网页验证或图片验证码页面，待真实书源双端验证。
5. 书源管理与脚本交互共用受控登录 WebView 和统一 Cookie Store；`startBrowserAwait` 可回传最终页面快照，普通 `java.webView` 仍是后台页面脚本执行器，二者生命周期保持分离。
6. WebView、Cookie、验证码、第三方登录和重定向尚无完整真实样本结果。
7. 普通规则书源也缺少固定样本的搜索、详情、目录、正文结果对照。
8. `preUpdateJs` 已移动到用户主动刷新目录的首请求前执行，首次、换源和后台目录加载默认不执行，对齐 Android `runPerJs`；脚本直接修改的 `book.tocUrl` 会带入请求，`java.reGetBook()`、`java.refreshTocUrl()` 也已通过受控回调接入同书源精确搜索和详情刷新，待真实动态目录书源验证。
9. URL `webView/webJs/webViewDelayTime` 与正文 `webJs/sourceRegex` 已进入受控 WebView；`sourceRegex` 通过页面开始时安装的 PerformanceObserver 和 Resource Timing 持续收集并匹配资源 URL，尚不是 Android `onLoadResource` 的原生实时拦截，极早终止或平台不记录的资源仍可能存在差异。

#### P0-01 内部实施顺序

| 顺序 | 子项 | 当前结论 | 对主流程的影响 |
|---:|---|---|---|
| P0-01A | 脚本同步网络语义 | 已加入异步宿主调用等待与同步结果重放，待真实书源验证 | 原 Promise 阻断已进入验证阶段，尚不能宣称关闭 |
| P0-01B | `book/chapter/source` 模型与变量语义 | 已加入规则链共享模型状态、变量优先级、模型方法和白名单字段回写，待真实书源验证 | 规则链内状态已贯通；脚本变更合并回持久领域实体仍待按业务结果逐项实现 |
| P0-01C | 正文脚本上下文 | 已贯通 `book/chapter/nextChapterUrl`，覆盖阅读、预加载、下载和单章换源 | 已进入真机验证阶段 |
| P0-01D | `loginCheckJs` 与交互策略 | 已执行登录检测、默认拒绝交互并提供持久设置开关；开启后接入可见验证页和 FIFO 单提示队列 | 实现完成，待真实书源 Android/iOS 验证 |
| P0-01E | `preUpdateJs`、WebView URL 选项和 `sourceRegex` | 生命周期及 `reGetBook/refreshTocUrl` 已接入，待真机验证；实时资源拦截仍有平台差距 | 动态目录、验证站和动态正文进入验证阶段 |
| P0-01F | `@put/@get` 与混合规则分词 | 已加入单次业务操作共享状态、变量优先级及普通/脚本混合求值，待真实规则验证 | 常见跨阶段变量传递进入验证阶段；复杂 `SourceRule` 分词仍需样本收口 |
| P1-COMPAT-A | 默认 UA、登录 Header、Cookie 与书源限流 | 已有部分基础设施，但请求生命周期未完全统一 | 造成 403、登录失效或触发反爬 |
| P1-COMPAT-B | 高频 Java/Rhino Helper 白名单 | 只支持基础子集 | 影响加密、字符集和聚合类书源 |

`P0-01D` 的非交互与可见交互底座已经落地：设置默认关闭，`loginCheckJs` 仍执行；交互 API 不返回伪造空值，而是以 `interactionRequired` 结束当前书源。设置开启后，搜索页作为唯一 UI 消费者串行处理确认、登录/网页验证和图片验证码；用户取消只结束当前书源，当前提示真正关闭后才派发下一条。该实现尚未通过真实登录书源和 Android/iOS 真机验证，因此不能把登录验证兼容写成已验收。

#### 内置书源静态影响面

2026-07-21 对 `assets/default_data/book_sources.json` 中 79 个内置书源进行字符串特征扫描，结果只用于确定开发顺序，不代替真实网络和规则验收：

| 特征 | 涉及书源数 | 风险判断 |
|---|---:|---|
| `java.ajax/connect/get/post/head` 同步网络调用 | 40 | 不是长尾问题，必须先解决执行语义 |
| `startBrowser/startBrowserAwait/getVerificationCode` | 17 | 需要交互权限策略与 WebView 验证边界 |
| `loginCheckJs` | 7 | 已进入响应链，待真实响应对象和交互分支验证 |
| `book/chapter.getVariable/putVariable` | 6 | 已进入共享模型状态与变量桥，待真机验证 |
| `@put/@get` | 7 | 已接入共享状态和读取优先级，待 7 个命中书源逐段验证 |
| `Java.type/Packages.*` | 11 | 必须建立跨平台白名单或明确拒绝 |

同一书源可能同时命中多项，以上数量不能相加。特征扫描只说明规则文本中出现相关调用，不证明网站当前可访问，也不证明每条调用一定经过本次搜索路径。

| P1-COMPAT-A 请求策略 | 新增统一书源 Header/限流服务，并接入 `source_url_resolver.dart`、`legado_script_bridge.dart`、`standard_source_service.dart` | 默认 User-Agent、书源 Header、登录 Header、URL Header、Cookie 和 `concurrentRate` 在普通请求与脚本请求中保持同一语义 |
| P1-COMPAT-B Helper 白名单 | `lib/src/api/js/java_compatibility_bridge.dart`、`legado_script_bridge.dart` | 按真实样本补精确方法名、参数重载、字符集、字节、加密、时间和 Jsoup 能力；iOS 无法实现的任意 JVM API 明确拒绝 |

P0-01A 没有通过正则给所有 `java.ajax(...)` 自动插入 `await`。当前实现采用有限同步重放协议：首次遇到 Dart Future 时结束本次 QuickJS 尝试，等待统一网络层完成，再从头执行规则；已经执行过的宿主调用按原顺序同步返回已保存信封，避免重复请求、Cookie/缓存写入和 `java.put` 副作用。该协议不阻塞 Flutter UI isolate，并继续复用现有网络、Cookie、超时和取消边界。

同步重放仍需 S4 等真实书源确认。脚本自身在宿主调用前修改 QuickJS 全局变量时，纯 JavaScript 语句会随重放再次执行；如果调用顺序发生变化，当前实现会明确报告“同步宿主调用重放路径发生变化”，不能把不确定结果当作成功。验证中若发现目标书源依赖不可重复的纯 JS 全局副作用，再决定是否增加执行 Scope 快照，不提前引入第二套网络栈。

P0-01B 已增加 `LegadoScriptModelState`：脚本只修改当前业务规则链的受控快照，URL、`bodyJs`、`loginCheckJs` 和解析字段复用同一状态，不直接持有数据库实体或 UI 对象。当前字段修改用于同一规则链后续步骤；哪些修改需要合并回书架持久实体，仍需按 Android 业务入口逐项核对，不能把任意脚本赋值直接写库。

P0-01E 已把目录 `preUpdateJs` 从解析器的“每页响应后”调整到服务层，并增加 Android `runPerJs` 对应的显式开关：首次、换源和后台静默目录加载保持关闭，用户从详情菜单主动刷新或重试目录时在首请求前执行一次。脚本快照中的 `bookUrl/tocUrl` 修改会决定首个目录地址。`java.refreshTocUrl()` 会使用当前脚本书籍快照重新请求详情，`java.reGetBook()` 会先按书名和作者在同一书源精确搜索、合并候选变量并替换 `bookUrl`，再请求详情；两者只在 `preUpdateJs` 上下文暴露，内部搜索按目录操作执行，默认不会申请搜索交互。URL 选项 `webView/webJs/webViewDelayTime` 与正文规则 `webJs/sourceRegex` 复用后台 WebView、统一 Cookie、超时和取消边界；POST 按 Android 顺序先走统一 HTTP，再把响应 HTML 载入页面环境。当前跨平台插件没有统一的子资源原生回调，页面开始时会安装 PerformanceObserver、扩大 Resource Timing 缓冲区并持续记录资源 URL，最终由 `sourceRegex` 选择首个匹配项；该近似边界仍必须通过动态媒体或接口书源真机确认。

P0-01F 已增加 `LegadoScriptExecutionState`，搜索、详情、目录和正文各自的 URL、`bodyJs`、`loginCheckJs` 与字段解析共享模型状态和临时变量；每次操作创建状态时预载书源变量，因此纯 `@get` 不依赖启动 QuickJS。`@put:{key: rule}` 使用页面根内容求值，`@get:{key}` 按章节、书籍、规则临时状态、书源变量读取。当前实现覆盖常见非嵌套 `@put` 对象；原生 `SourceRule` 对极复杂组合符、替换表达式和阶段边界的全部细节仍需由真实命中样本验证。

#### 搜索期登录与验证交互策略

当前 Flutter 搜索会执行 `loginCheckJs`，但默认不会自动弹出登录窗口：脚本上下文携带业务操作和交互策略，`startBrowser/startBrowserAwait/getVerificationCode` 在默认策略下返回稳定的 `interactionRequired`。搜索协调器沿用单书源失败隔离，其他并发书源继续执行。

后续补齐兼容能力时，Flutter 不照搬原生 Android 在搜索过程中由书源脚本直接弹出登录、浏览器验证或验证码界面的默认行为。搜索是多书源并发流程，任意书源都不应默认打断用户或阻塞整批搜索。

- 设置页已增加“搜索时允许书源登录与验证提示”持久开关，默认关闭；
- 开关关闭时仍执行 `loginCheckJs`，保留它对响应、Cookie 和登录状态的非交互处理能力；
- 搜索脚本调用 `startBrowser`、`startBrowserAwait`、验证码或登录导航等交互能力时，不显示弹窗、不打开页面、不等待用户输入；
- 需要返回值的交互 API 不使用伪造空值继续解析，而是返回稳定的“需要用户交互”失败，由搜索协调器只结束当前书源并继续其他书源；
- 搜索期脚本产生的 Toast、Snackbar 等提示默认一并静默，失败原因保留在书源诊断信息和日志中；
- 用户仍可从书源管理、书籍详情或阅读菜单主动进入该书源的登录页面；
- 开关开启后允许搜索流程申请交互；应用级 FIFO 队列同一时间只派发一个提示，用户确认后进入受控登录/验证页或图片验证码输入，待真机样本验收；
- 换源搜索、后台刷新和离线下载同样默认使用无交互模式，不能在后台突然拉起登录或验证页面。

实现时应在脚本上下文中传递明确的业务操作类型和交互策略，例如 `search`、`changeSource`、`bookInfo`、`toc`、`content`、`download`，由宿主桥统一裁决交互 API；不能只在搜索页面拦截导航，否则 `loginCheckJs` 或 `jsLib` 仍可能从底层桥直接弹出页面。

当开关关闭且 `loginCheckJs` 请求用户交互时，宿主桥应返回稳定的“需要用户交互”错误。搜索协调器只把当前书源记为不可用并继续其他书源，不能返回伪造空字符串让后续规则继续解析，也不能把该错误升级成整次搜索失败。

#### 退出门禁

- 普通规则代表书源四段链路通过；
- 标准 JS 和 `jsLib` 代表书源四段链路通过；
- 同步网络/Rhino 强依赖书源得到明确支持或不支持结论；
- 登录/Cookie/WebView 至少有一个真实成功样本；
- 默认设置下，登录、验证和验证码书源不会打断搜索、换源搜索或后台任务；
- 开启搜索交互开关后，同一时间最多出现一个登录或验证请求；
- 每次失败能够定位到书源、阶段和 API，不出现空白结果或无限加载。

- Android/iOS 长按、放大镜、拖动手柄、复制、全选和分享菜单的真机行为；
- 连续模式跨段落、分页模式跨行选择，以及覆盖翻页手势与选择手势是否冲突；
- 高亮和下划线新增、重启恢复、启停、删除、切章退出选择与正文轻微变化后的重新定位；
- 整书换源后的章节索引可能随新目录变化，需要真实换源样本确认标注是否仍落在合理章节；
- Android 原生当前对用户高亮/下划线的创建入口并不完整，本轮按其 `BookContentProcess` 数据结构和样式类型补齐 Flutter 可用闭环，不宣称交互像素级等价。

正则高亮规则、高亮导入导出、颜色与线宽编辑、跨设备同步，以及 AI 清理/改写记录不属于 P1-02 首批，保持后续专项。

退出门禁：上述选区和标注路径在 Android 与 iOS 真机通过；在用户提供结果前保持 `IMPLEMENTED_PENDING_VERIFICATION`。

### P1-03 TTS、HTTP TTS 与后台朗读

原生 Android 已具备系统 TTS、HTTP TTS、后台服务、暂停恢复、媒体按钮和朗读配置。Flutter 当前尚未实现，只在后续能力面板中登记边界。

建议拆成三步：

1. 前台系统 TTS：当前段落、下一段、跨章节；
2. 后台朗读：音频焦点、通知/锁屏控制、暂停恢复；
3. HTTP TTS：配置导入、请求、缓存、错误和隐私边界。

如果用户日常主要使用听书，本项应提升到 P0-03 之后立即实施。

### P1-04 搜索分页与筛选

当前搜索已经支持并发限制、停止、失败重试、书源选择和严格书名作者聚合，但第一批只搜索第一页。

建议补齐：

- 多书源下一页调度；
- 单书源展开和继续分页；
- 按书源分组和类型筛选；
- 分页失败单独重试；
- 新搜索、停止和翻页之间的世代隔离；
- 结果排序在增量追加后保持稳定。

### P1-05 离线下载后台可靠性

状态：`IMPLEMENTED_PENDING_VERIFICATION`

已按“降低书源风控风险优先”完成首批实现：

- 全应用只有一个 `DownloadCoordinator`，章节请求使用全局持久化并发设置，默认 5、允许 1～8；不会按页面或书籍再创建第二套并发池；
- 两次真实书源请求至少间隔 1.5 秒，单次正文请求 45 秒硬超时，失败后按 2～10 秒退避，单章最多尝试 5 次；达到上限后标记失败并继续后续章节；
- `download_tasks` 持久化等待、运行、暂停、成功、失败、失败摘要和正文字符数；应用重启后继续未完成队列；
- 支持全部、单书、单章暂停/恢复，支持失败任务重试；
- 新增独立 `/downloads` 下载管理页，可从设置进入；展示全部网络书架书，支持选择章节范围、跨书汇总和删除真实离线正文；
- Android 接入 `dataSync` 前台 Service 和低打扰进度通知；
- iOS 接入系统有限后台任务窗口，窗口结束后保留队列，下次应用获得运行机会时续传；不承诺无限后台执行。
- 阅读器“更多 → 下载”提供默认关闭的“自动换源下载”：失败 5 次后使用固定单 worker 按 `3@98% → 5@95% → 8@90% → 12@85% → 20@80% → 30@70%` 梯度扩大范围，累计最多检查 78 个来源、每级最多深度验证 3 个候选、全局最多 3 分钟；每个已比较相邻章节都达到当前门槛才锁定，低于 70% 时提示手动换源，只改变下载来源，不静默修改书架主源；
- 每个下载批次记录实际尝试来源和最终成功来源，批次全部终止后按书源汇总 `成功章节/尝试章节`；高于 80% 加 1，低于 80% 减 1，等于 80% 不变，同一书源每本书每批只结算一次。

仍保留的明确边界：

- Android 被用户强制停止或被厂商系统彻底冻结后不能继续，请求队列会在下次启动恢复；
- iOS 不允许第三方阅读器长期任意执行网络任务，不能与 Android 前台 Service 等价；
- 暂未实现漫画或图片章节离线下载；
- 平台通知、退后台续传、系统回收恢复和真实书源限速效果均等待 Android/iOS 真机验证。

### P1-06 阅读失败后一键/自动换源

建议先做“当前章加载失败 → 一键搜索可用来源 → 用户确认”，再做自动换源。

自动换源至少需要以下保护：

- 有限候选数和超时；
- 只在明确网络/规则/空正文错误时触发；
- 不对付费、登录或验证码失败无限重试；
- 不静默更换整本书主源；
- 自动换源结果可回退并可查看来源；
- 防止多个失败章节同时启动无界搜索。

## 9. 建议的实际执行批次

### 批次 A：建立可量化主流程基线

1. 固定 10～20 个用户常用书源；
2. 固定搜索关键词和目标书籍；
3. 填写普通规则、标准 JS、`jsLib`、登录和 Rhino 强依赖分类；
4. 记录搜索、详情、目录、正文结果；
5. 建立失败 API 排名。

完成信号：能够回答“用户常用书源成功率是多少、失败主要集中在哪些 API”。

### 批次 B：关闭最高频兼容缺口

1. 优先修复影响多个样本的规则或脚本 API；
2. 完成至少一个真实 WebView 登录和 Cookie 回写样本；
3. 为无法跨平台等价的 Rhino/JVM 能力给出明确错误和书源级说明；
4. 将书源调试接入真实四段链路。

完成信号：代表书源可稳定完成搜索到正文，不靠偶然缓存或手工绕行。

### 批次 C：阅读稳定性与换源安全

1. 真机执行长章节、快速切章、重排、后台、杀进程和长时间阅读；
2. 修复分页性能、旧异步覆盖和进度倒退；
3. 验证整书换源事务、进度映射和新主键接管；
4. 验证单章换源持久化和刷新撤销。

完成信号：主流程可以作为日常阅读器连续使用，不丢书、不串章、不丢进度。

### 批次 D：阅读体验第一轮补强

1. 正文 HTML/图片/简繁/内容处理；
2. 文本选择、复制和基础高亮；
3. 搜索分页；
4. 阅读失败后一键换源；
5. 根据用户习惯选择先做 TTS 或后台离线下载。

完成信号：正文质量、坏源恢复和日常交互接近原生 Android 的主要使用体验。

### 批次 E：高级视觉和低频管理

仿真翻页、双页、字体、背景、样式导入导出、书源排序导出等按用户反馈逐项实施。

## 10. 建议用户确认的最终顺序

默认建议顺序为：

```text
真实书源兼容
→ 阅读稳定性与进度安全
→ 整书/单章换源验收
→ 正文内容处理
→ 文本选择/复制/高亮
→ 搜索分页
→ 一键/自动换源
→ TTS 或后台离线下载
→ 仿真翻页、双页、字体和背景
→ 其余非主流程功能
```

如果用户最常使用听书，则调整为：

```text
真实书源兼容
→ 阅读稳定性与换源安全
→ 前台系统 TTS
→ 后台朗读与媒体控制
→ 正文处理和搜索分页
→ 其余体验能力
```
