# 阅读器双侧边缘滑动退出实施分析

> 文档状态：`IN_PROGRESS / 代码已写入，等待用户 Android、iOS 真机验证`
>
> 创建日期：2026-07-27
>
> 适用范围：Flutter 小说文本阅读器 `/reader`
>
> Android 只读参考：`ReadBookScreen.kt` 的 `BackHandler`、阅读页面手势系统

## 1. 结论

建议左右两侧都提供边缘滑动退出，并默认开启：

- 从左侧屏幕边缘向右滑动：保存阅读进度并退出阅读界面；
- 从右侧屏幕边缘向左滑动：保存阅读进度并退出阅读界面；
- 不是从边缘起手：继续交给当前阅读模式处理，不改变覆盖、仿真、滑动、无动画、
  上下分页或连续滚动的现有行为；
- 设置页“系统”页签增加“边缘滑动退出”开关，默认开启；
- 边缘退出只发送现有 `CloseReaderIntent`，继续经过
  `ReaderViewModel._close()` 保存进度、恢复阅读系统状态并关闭路由，不直接调用
  `Navigator.pop()`。

双侧设计比仅右侧更适合左右手单手操作。两侧采用镜像方向可以把“从屏幕外向正文内拉”
作为统一心智模型，也能避免右侧被 Android 系统返回手势优先接管时完全失去应用内入口。

## 2. 唯一目标与不包含范围

本专项唯一目标：

> 为小说文本阅读器增加可持久化、默认开启的双侧边缘滑动退出，并与所有现有翻页方式、
> 文字选择、菜单和系统返回行为建立明确的手势优先级。

本专项不包含：

- 修改 PDF 阅读器；
- 修改原 Android 参考工程；
- 改变普通正文区域的翻页方向、距离阈值或动画外观；
- 新增第三方手势库或平台通道；
- 修改数据库 Schema、应用版本号或路由参数；
- 新增全屏任意位置滑动退出；
- 顺带重构正文加载、缓存、分页、书签、换源或下载业务。

## 3. 当前 Flutter 实现事实

### 3.1 退出链路

当前退出已经具有统一业务入口：

```text
顶部返回 / Android、iOS 系统返回
  -> CloseReaderIntent
  -> ReaderViewModel._close()
  -> _saveProgress()
  -> ExitReaderSystemEffect
  -> CloseReaderRouteEffect
  -> ReaderRoute 设置 _allowPop
  -> Navigator.pop()
```

边缘手势不能直接关闭路由。复用 `CloseReaderIntent` 才能保证章节 URL、章节索引、字符位置和
摘要锚点在退出前保存，同时恢复系统栏、常亮、亮度和方向状态。

当前 `PopScope` 在 `_allowPop=false` 时拦截系统返回并发送同一个 Intent。新增手势后需要给
关闭过程增加单飞保护，防止系统边缘返回和应用内边缘手势同时触发两次保存或两次退出。

### 3.2 当前翻页与选择手势

| 阅读方式 | 当前手势入口 | 边缘退出需要避免的冲突 |
|---|---|---|
| 左右覆盖、仿真 | `ReaderPagedContent` 外层水平拖动 | 不能先启动卷页，再中途改成退出 |
| 左右滑动、无动画 | 横向 `PageView` | 边缘起手时不能让 `PageView` 抢先翻页 |
| 上下分页 | 纵向 `PageView` | 横向退出不能吞掉普通纵向翻页 |
| 连续滚动 | 纵向 `ListView` | 横向退出不能影响普通纵向滚动 |
| 原生文字选择 | `SelectionArea` + `ReaderSelectionRegion` | 长按、选择手柄和上下文菜单不能被误判 |
| 正文短按 | 被动 `ReaderTapRegion` | 边缘短按不应退出，仍可执行配置的点击动作 |

现有 `ReaderTapRegion` 使用 `Listener` 被动观察短按，不参加 Flutter 手势竞技场；覆盖和仿真
翻页则使用水平拖动识别器。若简单在页面两侧叠加固定透明 `GestureDetector`，会让边缘区域的
点击、长按选词和纵向滚动全部无法到达正文，因此不采用这种实现。

### 3.3 配置持久化

`ReaderDisplayConfig` 当前由 `ReaderRepository` 以全局 JSON 缓存在 `caches` 表中持久化，
旧的按书配置只在全局配置不存在时迁移一次。新增布尔字段可继续进入同一 JSON：

- 新安装默认值为 `true`；
- 旧缓存缺少字段时读取为 `true`；
- 用户关闭后保存为 `false`，后续打开其他书也保持用户选择；
- 不新增缓存键，不修改表结构，不升级 `LegadoDatabase.schemaVersion`；
- 不修改 `pubspec.yaml` build number。

字段建议命名为 `edgeSwipeToCloseEnabled`。

## 4. 推荐手势架构

### 4.1 使用祖先级边缘识别器

新增独立 UI 文件：

```text
lib/src/ui/reader/reader_edge_swipe_exit.dart
```

由 `ReaderScreen` 在物理屏幕范围包裹正文，使用 `RawGestureDetector` 注册一个只接受边缘起手的
水平拖动识别器。识别器是正文的祖先而不是盖在正文上面的透明兄弟层，因此：

- 非边缘起手在 `PointerDown` 时立即拒绝，完全不进入后续翻页竞争；
- 边缘短按没有水平位移时不接受手势，正文点击仍能收到；
- 边缘长按没有水平位移时不接受手势，原生文字选择仍有机会获胜；
- 边缘纵向移动时由 `ListView` 或纵向 `PageView` 获胜；
- 边缘正确水平移动时，边缘识别器使用较小但受控的触摸松弛距离先取得手势控制，
  下层横向分页器不会同时翻页。

识别器只负责瞬时 UI 手势状态，不读取数据库、不保存进度、不导航。

### 4.2 物理边缘命中

识别区域必须位于 `Scaffold` 根部、正文 `SafeArea` 外侧，按设备物理屏幕边缘计算。

建议基础命中宽度为 `24 logical px`。对于系统提供较大
`MediaQuery.systemGestureInsets` 的设备，应用内识别范围可以向内补足少量可触达区域，但最大限制为
`32 logical px`，避免占用过多正文：

```text
左侧命中宽度 = clamp(max(24, systemGestureInsets.left + 6), 24, 32)
右侧命中宽度 = clamp(max(24, systemGestureInsets.right + 6), 24, 32)
```

这一区域只决定“是否为边缘候选”。手指开始移动后可继续进入正文区域，不要求始终停留在窄边缘内。

### 4.3 方向和提交阈值

| 起手位置 | 唯一有效方向 | 结果 |
|---|---|---|
| 左侧边缘 | `dx > 0`，向右进入屏幕 | 退出 |
| 右侧边缘 | `dx < 0`，向左进入屏幕 | 退出 |
| 任一边缘反方向 | 朝屏幕外移动 | 取消，不转为翻页 |
| 非边缘 | 任意方向 | 不参与，交给原阅读手势 |

提交条件建议采用“距离或速度”二选一，但快速甩动仍需要超过最小触摸距离：

```text
距离阈值 = clamp(屏幕宽度 × 18%, 56, 96 logical px)
或
正确方向速度 >= 700 logical px/s 且距离 >= Flutter kTouchSlop
```

边缘候选一旦开始，不能在同一指针序列中改判为普通翻页。未达到退出阈值时只取消本次退出，
不补做翻页，避免松手瞬间突然翻页。

### 4.4 手势状态机

```text
idle
  -> 非边缘按下：立即拒绝，正文手势继续
  -> 边缘按下：candidate

candidate
  -> 纵向移动占优：拒绝，纵向滚动/分页继续
  -> 正确水平移动超过松弛距离：dragging
  -> 反向水平移动：保持取消候选
  -> 未移动松手/长按：不退出

dragging
  -> 达到距离或速度阈值：committed
  -> 未达到阈值松手/系统取消：cancelled

committed
  -> 只发送一次 CloseReaderIntent
  -> 等现有保存和路由 Effect 完成
```

Widget 销毁、配置关闭、菜单出现或路由退出时，立即清理当前指针、速度和进度状态。不得保留
Timer、Stream、历史轨迹或全屏位图。

## 5. 用户反馈与动画

边缘拖动期间建议只在起手侧显示轻量的圆形返回箭头和进度反馈：

- 箭头随有效位移在很小范围内向屏幕内移动；
- 达到提交阈值时改变强调色或缩放，提示松手会退出；
- 取消时使用 `DurationToken.short` 回弹并淡出；
- 提交后立即发送关闭 Intent，不自行模拟整页路由返回动画；
- 反馈层使用 `IgnorePointer` 和 `RepaintBoundary`，只重绘小范围提示，不平移正文。

不建议让整张正文跟手平移。覆盖/仿真模式本身已有复杂页面动画，整页退出位移会增加绘制层级，
也容易让用户误以为正在翻页。

## 6. 与现有功能的兼容规则

### 6.1 覆盖和仿真翻页

- 边缘起手由边缘识别器先取得水平手势，`ReaderPagedContent` 不创建翻页目标页；
- 非边缘起手继续执行当前 `22% / 500 px/s` 的覆盖或仿真提交规则；
- 已经开始的覆盖/仿真动画期间忽略新的边缘退出；
- 已有有效文字选区或选择手柄正在拖动时，由系统选区 Overlay 优先；
- 边缘退出提交后不再等待卷页动画，直接进入统一保存退出链路。

### 6.2 滑动、无动画和其他分页

- 左右 `PageView` 仅在非边缘起手时得到水平拖动；
- 上下 `PageView` 的纵向识别保持不变；
- 边缘手势取消后不调用 `jumpToPage` 或 `animateToPage`；
- 页码和稳定字符锚点只由原翻页逻辑更新，取消退出不写阅读进度。

### 6.3 连续滚动

- 非边缘水平移动仍无新增动作；
- 纵向滚动继续由 `ListView` 处理；
- 从边缘正确向内横滑才退出；
- 边缘退出不根据滚动像素修改字符锚点，退出时保存当前已有稳定位置。

### 6.4 菜单、设置和其他面板

- 阅读菜单显示时禁用边缘退出，用户可使用顶栏返回按钮；
- 设置、目录、书签、搜索、换源和下载等 Modal Sheet 位于更高 Overlay，自身优先处理手势；
- 活跃 Sheet 关闭后恢复边缘退出；
- 加载或错误状态仍允许边缘退出，避免正文请求失败时只能依赖系统返回。

### 6.5 Android 与 iOS 系统返回

- Android 手势导航可能先截获左右系统边缘。若系统接管，现有 `PopScope` 发送
  `CloseReaderIntent`，结果仍是保存后退出；
- 若系统没有接管，Flutter 边缘识别器执行相同 Intent；
- iOS 当前阅读路由不依赖 Cupertino 交互返回，应用内双侧识别器提供一致入口；
- 不尝试拦截或关闭操作系统返回手势；
- ViewModel 的关闭单飞保护保证系统回调和 Flutter 手势同时到达时只执行一次。

## 7. 设置交互

在“显示设置 → 系统”增加：

```text
边缘滑动退出                     [开关]
从左右屏幕边缘向内滑动，保存进度并退出阅读
```

规则：

- 默认开启；
- 应用按钮提交完整 `ReaderDisplayConfig`；
- 关闭后不注册边缘退出识别器，所有边缘触摸恢复为原正文手势；
- 设置是设备级全局阅读偏好，与现有阅读显示配置作用域一致；
- 不增加左右侧独立开关，避免设置复杂化；两侧行为固定镜像。

## 9. 性能和内存约束

1. 非边缘起手在按下阶段立即拒绝，不让每次翻页持续经过额外计算。
2. 只跟踪一个主指针，保存起点、累计位移、速度和单个进度值，不保存轨迹列表。
3. 拖动反馈只重绘边缘小区域，不移动或重建正文、分页结果和图片页。
4. 不创建全屏截图、`ui.Image`、模糊图层或大范围 `saveLayer`。
5. 不创建 Timer、Stream、平台监听器或新的 `AnimationController` 长生命周期集合。
6. 若使用一个短时反馈控制器，必须在 `dispose` 中释放，并在路由退出时停止。
7. 不因边缘手势触发分页、正文重排、后台预下载或配置写入；只有用户应用开关时保存配置。
8. 关闭 Intent 单飞，避免重复进度写入和重复平台恢复。

## 10. 风险与处理

| 风险 | 处理 |
|---|---|
| 边缘退出与横向翻页同时启动 | 边缘限定祖先识别器先接受；非边缘立即拒绝；同一指针不允许中途改判 |
| 透明边缘层吞掉点击、长按和纵向滚动 | 不使用顶部透明条，改用祖先级 `RawGestureDetector` |
| 系统返回和应用手势重复关闭 | `ReaderViewModel._close()` 增加单飞保护 |
| Android 系统手势先截获边缘事件 | 保留系统手势，由 `PopScope` 进入同一关闭链路 |
| 快速误触导致退出 | 正确方向、最小位移、距离/速度阈值和进度反馈共同约束 |
| 取消退出后意外翻页 | 边缘候选取消即结束，不补做翻页 |
| 仿真动画或选区正在进行 | 已有动画期间忽略新退出；系统选择 Overlay 优先命中 |
| 菜单或 Sheet 内误触退出 | 菜单显示时禁用；Modal Sheet 位于更高 Overlay |
| 大屏需要拖动过远 | 距离阈值限制在 `56～96 logical px` |

## 11. 用户验收清单

代码实施后由用户运行和真机验收，AI 不执行构建、分析、测试、格式化或应用启动。

### 11.1 基础行为

1. 打开阅读设置“系统”，确认“边缘滑动退出”默认开启。
2. 从右侧物理边缘向左滑动，确认保存进度后只退出一次。
3. 从左侧物理边缘向右滑动，确认行为与右侧一致。
4. 从正文内部向左或向右滑动，确认仍执行当前翻页，不退出。
5. 关闭开关并应用，确认两侧边缘恢复原正文手势；重新打开书后仍保持关闭。
6. 再次开启，确认打开其他书也保持开启。

### 11.2 阈值和误触

1. 边缘轻点，确认不退出，仍执行对应点击区域动作。
2. 边缘向内短距离拖动后松手，确认提示回弹且不退出、不翻页。
3. 左边缘向左、右边缘向右反向拖动，确认不退出、不补做翻页。
4. 从边缘纵向滚动，确认连续模式或上下分页仍可使用。
5. 快速正确方向甩动，确认超过最小位移后可退出。

### 11.3 翻页和选区兼容

1. 分别在覆盖、仿真、滑动和无动画模式测试双侧退出与正文内部翻页。
2. 仿真卷页拖动和回弹过程中尝试第二次边缘手势，确认不会叠加退出或破坏页码。
3. 长按边缘附近与正文内部文字，确认非水平长按仍可选择文字。
4. 拖动选择手柄、使用复制/分享/高亮/下划线菜单，确认不会误退出。
5. 取消边缘退出后检查页码与章节字符位置没有变化。

### 11.4 路由和恢复

1. 边缘退出后重新进入，确认恢复到退出前章节和接近原字符位置。
2. 在正文加载、正文错误和相邻章节加载状态下边缘退出，确认都能返回。
3. 菜单显示时从边缘拖动，确认不退出；使用顶栏返回正常保存退出。
4. 设置、目录、书签、搜索、换源和下载 Sheet 打开时测试边缘，确认只操作当前面板。
5. Android 手势导航和三键导航各测试一次；iOS 左右两侧各测试一次。
6. 快速连续执行系统返回和边缘退出，确认不重复弹回两层路由、不重复提示。
