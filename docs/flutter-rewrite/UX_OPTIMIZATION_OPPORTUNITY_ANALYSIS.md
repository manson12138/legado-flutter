# PageNest（拾页）体验优化机会分析

> 文档状态：`PROPOSED / 等待用户确认执行范围`  
> 静态梳理日期：2026-07-30  
> 适用范围：应用启动、书架/历史、搜索、书源、详情、阅读器、本地导入、下载管理和“我的”。  
> 本轮边界：只阅读文档与源码，没有修改业务代码，也没有运行构建、测试、分析、格式化或应用。

## 1. 结论摘要

当前项目已经具备正式应用 Shell、统一主题、书架/历史双页、渐进详情、完整阅读器、下载管理和换源等大量体验代码。下一轮体验优化的重点不应继续堆叠动画或入口，而应优先处理三类问题：

1. **先关闭体验验收债务**：`P0_PENDING_VERIFICATION_CHECKLIST.md` 的真实书源、阅读稳定性和换源安全仍全部是 `NOT_RUN`。这些问题决定“能不能稳定日用”，优先级高于新的视觉功能。
2. **把失败和空状态变成可继续的路径**：书源管理已经使用统一加载/空态/错误组件，但书架、历史和搜索仍有直接展示转圈或文字、缺少重试和跨页面行动的问题。
3. **减少面向开发阶段的界面信息**：详情页和阅读器仍向普通用户展示“后续能力”“Android 详情页后续能力”等内部迁移说明；这些信息适合文档，不适合正式产品主流程。

建议先执行“体验收口包”，再做搜索分页、一键换源、后台任务中心和 TTS 等新增能力。

## 2. 静态审计依据

### 2.1 已有基础

- `WelcomeScreen` 已提供“书架 / 搜索 / 书源 / 我的”四个稳定一级入口。
- `AdaptiveAppScaffold` 已按 600/840 logical pixels 切换底部导航与 NavigationRail。
- `AppLoadingView`、`AppEmptyView`、`AppErrorView` 已存在，可以直接作为跨页面状态规范的基础。
- 详情页已支持搜索快照渐进渲染、后台静默刷新和目录错误回退。
- 阅读器已具备稳定字符锚点、分页、连续阅读、设置、选区、标注、下载、整书/单章换源入口和内存压力处理。
- 下载、书架后台更新和远程书源同步已经是跨页面运行的应用级任务。

### 2.2 当前可见的不一致

| 观察 | 当前事实 | 用户影响 |
|---|---|---|
| 页面状态不统一 | 统一状态组件目前主要用于书源和整书换源；书架、历史、搜索仍直接使用 `CircularProgressIndicator` 或普通 `Text` | 用户遇到错误或空数据后不知道下一步 |
| 搜索书源入口重复 | 搜索页 AppBar 有书源 PopupMenu，正文又有独立书源选择面板 | 两套选择语义容易让用户不确定当前生效范围 |
| 空书架缺少行动 | 空书架仅提示“请先从搜索详情加入书籍” | 用户还要自己切换一级页面，首次使用路径变长 |
| 历史空态和错误不可恢复 | 历史页空态只有文字，错误态没有重试 | 数据恢复失败时没有直接出口 |
| 开发说明进入产品界面 | 详情页有“Android 详情页后续能力”，阅读器有“后续能力”清单 | 暴露迁移状态，增加无效认知负担 |
| 本地导入能力文案不一致 | 页面提示主要写 TXT/EPUB；组合根实际还注册 PDF/UMD，文件选择范围又可能更大 | 用户无法在选择前知道什么能读、什么会被拒绝 |
| 后台任务反馈分散 | 下载、书架刷新、书源同步分别在自己的页面展示，其他页面主要依赖短暂 SnackBar | 离开页面后难以知道任务是否仍在运行或失败 |
| 大页面更新粒度偏粗 | 搜索、详情、下载页面文件和状态面较大，多个增量区域由同一页面状态驱动 | 真机上可能出现无关区域重建、滚动或动画抖动，需要性能验收确认 |

## 3. 优化机会与优先级

### UX-00：建立“日用体验基线”

优先级：`P0`  
规模：`M`  
依赖：用户提供 Android/iOS 真机与真实书源结果。

执行内容：

- 先完成现有 P0 清单的真实书源、长时间阅读、重排恢复、前后台、杀进程和换源事务验证。
- 在已有匿名授权边界内，只记录用户可感知指标：启动可交互、搜索首个结果、详情首屏、目录可用、阅读正文首帧、切章、恢复位置和慢帧分类。
- 把“代码已写入”和“用户体验已通过”分开记录。
- 当前封面转场诊断日志完成定位后，按既有日志移除规则只清理本任务加入的日志及其专用变量/方法。

验收重点：

- 不丢书、不串章、不回退进度。
- 弱网和失败路径有可操作反馈。
- 书架/历史进入阅读器没有明显白屏、重复 loading 或不可解释卡顿。

### UX-01：统一加载、空态、错误和恢复行动

优先级：`P0`  
规模：`S～M`  
数据影响：无 Schema、MMKV 或安全存储变化。

建议把已有 `AppLoadingView`、`AppEmptyView`、`AppErrorView` 扩展为统一状态契约，但文案和行动必须由 Feature 提供：

| 页面 | 空态/错误后的主行动 |
|---|---|
| 书架为空 | “去搜索” + “导入本地书” |
| 当前分组为空 | “查看全部书籍”或“移动书籍到本组” |
| 阅读历史为空 | “打开书架” |
| 搜索无书源 | “去书源管理” |
| 搜索全停用 | “全部启用”或“管理书源” |
| 搜索无结果 | “调整匹配方式” + “查看失败书源” |
| 详情/目录失败 | “重试当前来源” + “切换候选来源” |
| 阅读正文失败 | “重试” + “单章换源” + “读取离线缓存（存在时）” |

加载体验建议：

- 已有本地快照时保持旧内容，使用局部刷新提示，不回退到全屏转圈。
- 只有首次且没有任何可展示事实时才使用全屏加载。
- 长于用户预期的操作显示当前阶段和可取消入口，避免只有无限进度。

### UX-02：清理面向开发阶段的“未来能力”入口

优先级：`P0`  
规模：`S`  
数据影响：无。

建议：

- 从正式详情页移除“Android 详情页后续能力”面板。
- 从阅读器常用菜单移除“后续能力”列表。
- 已实现能力进入真实操作入口；未实现能力默认不展示。
- 如果确实需要收集内测反馈，放入“关于 → 实验性功能”，并明确这是内测功能，不展示内部阶段名、文件边界或迁移原因。

验收重点：

- 普通用户看不到 P2/P3、M11、Android 对照或“待接入”等开发术语。
- 不出现可点击但没有业务结果的按钮。

### UX-03：合并搜索书源选择并补齐零书源引导

优先级：`P0`  
规模：`M`  
数据影响：继续复用现有搜索偏好，不新增存储。

建议：

- 保留一套书源选择面板，AppBar 只显示当前范围摘要和入口，不再提供第二套逐项 PopupMenu。
- 面板顶部展示“已选数量 / 启用数量”、分组、名称搜索、成功率筛选和匹配方式。
- 保存后在搜索框附近显示紧凑摘要，例如“全部启用书源”或“玄幻组 · 12 个”。
- 无书源、全停用、当前选择为零时给出不同原因和对应行动。
- 变更书源范围后明确提示“下次搜索生效”或提供“立即重新搜索”，避免状态已经变化但结果仍属于旧范围。

### UX-04：本地导入前置能力说明与结果收口

优先级：`P0`  
规模：`M`  
数据影响：无新增持久化。

建议把当前“选择文件 → 批量加入书架”升级为四个明确阶段：

```text
选择文件
→ 能力预检（支持 / 受限支持 / 不支持 / DRM）
→ 冲突与导入选项
→ 结果汇总（新增 / 更新 / 跳过 / 失败）
```

具体要求：

- 选择前显示当前真实支持矩阵，文案与 Parser Registry 保持一致。
- 文件选择器不要宣称尚无解析器的格式可用；如果平台必须显示，选择后立即给出明确拒绝原因。
- EPUB 图片/封面受限、MOBI/AZW/压缩容器未实现等边界使用用户语言说明，不显示内部阶段编号。
- 导入结束后可以直接“查看书架”或“打开第一本成功导入的书”。

### UX-05：应用级后台任务中心

优先级：`P1`  
规模：`M～L`  
依赖：复用现有下载、书架刷新、远程书源同步状态流；不另建第二套任务状态。

建议在一级 Shell 提供低打扰任务入口：

- 导航或顶栏使用小型 Badge 表示运行中/失败任务数量。
- 统一汇总下载、书架目录更新、远程书源同步和批量导入。
- 展示任务来源、进度、失败数量、暂停/继续/重试和进入详情。
- 完成提示不阻断当前阅读；失败保持可回看，不只依赖短暂 SnackBar。
- 阅读器内只展示与当前书有关的任务，完整管理仍进入任务中心。

### UX-06：阅读失败的一键恢复路径

优先级：`P1`  
规模：`M～L`  
依赖：先通过手动整书/单章换源安全验收。

建议按以下顺序实施：

1. 当前章失败页同时提供“重试”和“单章换源”。
2. 存在离线正文时优先提供“使用已缓存内容”。
3. 单章换源搜索成功后先展示来源和章节匹配，再由用户确认。
4. 后续再考虑受控自动换源；不得静默修改整本书主源。

这是比继续调仿真翻页更直接的日用体验提升。

### UX-07：搜索分页、候选持久化和结果可解释性

优先级：`P1`  
规模：`L`  
数据影响：候选持久化方案会使用 SQLite，需要按现有设计评估 Schema v10 和 build number 联动。

建议：

- 补多书源下一页与单源继续搜索，分页失败独立重试。
- 结果列表区分“主要来源”和“其他来源”，并说明排序依据。
- 保持结果追加后的稳定顺序，不让用户正在查看的 Cell 跳动。
- 执行现有 `m06/04_search_book_source_candidates_persistence_design.md` 前，先确认 Schema v10 方案；完成后详情、阅读器和下载入口可复用完整候选，不必再次盲搜。

### UX-08：书架的“继续阅读”与最近活动

优先级：`P1`  
规模：`M`  
数据影响：优先复用现有书架和历史快照，不新增表。

建议：

- 书架顶部提供一张可关闭的“继续阅读”条目：封面、书名、当前章节、最近阅读时间和进度。
- 只在存在可靠阅读历史时展示；游客/账号继续按当前作用域隔离。
- 点击直接进入阅读，长按或次要操作进入详情。
- 不与书架排序重复维护数据，完全由现有历史事实派生。

### UX-09：弱网、离线和缓存可见性

优先级：`P1`  
规模：`M`  
依赖：优先复用统一网络错误分类，不仅依靠“是否有网络”的单一布尔值。

建议：

- 详情、目录和阅读器明确区分 DNS、超时、HTTP、登录验证、规则失败与取消。
- 书籍/章节展示“已离线”或“仅在线”状态，但不使用颜色作为唯一表达。
- 弱网时保留已展示内容并允许手动刷新，不因后台刷新失败清空页面。
- 下载页显示近似占用空间、最近失败原因和下次恢复条件。

### UX-10：高风险操作提供可撤销或恢复说明

优先级：`P1`  
规模：`M～L`  
数据影响：需要逐项评估，不能用 UI 假撤销掩盖已经提交的不可逆事务。

建议优先覆盖：

- 书架移除；
- 批量停用书源；
- 删除下载任务但保留正文；
- 清除离线正文；
- 清空搜索历史。

能安全延迟提交的操作使用“撤销”；不能撤销的操作在确认框中明确说明会保留和会删除的内容。

### UX-11：可访问性与减少动态效果专项

优先级：`P2`  
规模：`M`  
依赖：Android/iOS 真机和系统辅助功能验证。

专项覆盖：

- 系统文字缩放 1.0、1.3、2.0；
- TalkBack/VoiceOver 的阅读顺序、按钮标签、进度播报和选择状态；
- “减少动态效果”下关闭封面放大、仿真卷页和非必要淡入；
- 深色模式、对比度、颜色非唯一表达；
- 平板键盘、方向键、回车/空格和焦点可见性；
- 阅读器手势与系统返回、文字选择、屏幕阅读器冲突。

### UX-12：宽屏主从布局

优先级：`P2`  
规模：`L`

当前 Shell 已切换 NavigationRail，但多数 Feature 仍是放大的单栏页面。可按频率逐步实现：

- 书架/历史左侧网格，右侧详情预览；
- 书源列表/编辑双栏；
- 搜索结果/详情双栏；
- 下载书籍/章节双栏；
- 横屏阅读器双页作为独立专项。

### UX-13：感知性能与重建边界

优先级：`P2`，但发现真机卡顿时立即提升到 `P0/P1`  
规模：`M～L`

建议只在真机证据下实施：

- 有快照时使用 stale-while-revalidate，不闪回全屏 loading。
- 搜索进度、失败摘要、分类栏和结果列表拆成可独立重建区域。
- 详情页封面、操作卡、目录和后台刷新状态隔离重建。
- 网络封面按实际显示尺寸解码，限制内存缓存规模。
- 长列表保持稳定 key，并确认滚动位置不会被增量结果重排破坏。
- 仿真翻页、图片正文和封面转场继续使用有限 `RepaintBoundary`，避免全屏快照常驻内存。
- 任何 Timer、Controller、Stream 和平台监听都必须随 Route/State 关闭。

### UX-14：TTS 是否前移由真实使用习惯决定

优先级：默认 `P2`；听书是主要场景时提升到 `P1`  
规模：`L`

建议顺序：

1. 前台系统 TTS；
2. 跨段落、跨章节和进度同步；
3. 音频焦点、后台播放、通知/锁屏控制；
4. HTTP TTS、缓存和配置导入。

不建议在前台 TTS 尚未稳定前同时实现后台服务和 HTTP TTS。

## 4. 推荐执行批次

### 批次 A：体验收口包（建议首先执行）

包含：`UX-00`、`UX-01`、`UX-02`、`UX-03`、`UX-04`。

目标：

- 先拿到日用稳定性证据；
- 所有核心页面遇到空、错、无书源或不支持格式时都能继续操作；
- 移除内部迁移术语和重复入口；
- 不新增数据库字段或第三方依赖。

### 批次 B：发现与恢复

包含：`UX-06`、`UX-07`。

目标：

- 搜不到时可以继续翻页或调整范围；
- 读不到时可以一键尝试当前章换源；
- 完整候选可以跨详情、阅读和下载复用。

注意：候选持久化涉及 SQLite，执行前必须单独确认 Schema v10、基础建表、`onUpgrade` 和 `pubspec.yaml` build number 联动。

### 批次 C：持续使用体验

包含：`UX-05`、`UX-08`、`UX-09`、`UX-10`。

目标：

- 后台任务离开页面后仍可理解和管理；
- 打开 App 能更快继续上次阅读；
- 弱网、离线和删除行为可预测。

### 批次 D：专项能力

包含：`UX-11`、`UX-12`、`UX-13`、`UX-14`。

按真机反馈、设备类型和用户是否常用听书决定顺序。

## 5. 不建议现在优先做的项目

- 在仿真翻页尚待真机收口时继续增加更多装饰动画。
- 未解决搜索第一页限制前增加复杂发现页。
- 把所有页面同时改成全新视觉，导致无法逐项验收。
- 为显示“任务中心”复制下载或同步状态，形成第二套状态机。
- 仅凭静态源码对性能做大规模重构；应先从用户可感知指标和真机慢帧定位。
- 在前台 TTS 未稳定前一次性接入后台服务、HTTP TTS 和完整媒体控制。

## 6. 建议的下一步

默认建议先执行“批次 A：体验收口包”，内部顺序为：

```text
完成 P0 真机基线
→ 统一核心页面状态与行动
→ 合并搜索书源入口
→ 收口本地导入能力说明
→ 移除开发阶段未来能力入口
```

本轮只完成分析，等待用户确认后再进入具体代码任务。
