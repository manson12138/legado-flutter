# 搜索书源空状态分流与书源页提示设计

状态：`CODE_WRITTEN / 等待用户运行验证`

## 1. 目标

搜索提交前明确区分以下三种情况，避免当前统一提示“请至少选择一个可用书源”掩盖真实原因：

1. 当前一本可见书源都没有：
   - 直接进入书源管理界面；
   - 进入后提示：`当前没有书源，请添加书源`。
2. 存在可见且全局已启用的书源，但搜索界面没有选择任何可执行书源：
   - 留在搜索界面；
   - 弹出确认框：`当前没有开启搜索书源，是否全部开启`；
   - 用户确认“全部开启”后，恢复搜索页全部书源范围并立即继续本次搜索；
   - 用户取消时保留原选择，不发起搜索。
3. 存在可见书源，但书源管理中的全局启用开关全部关闭：
   - 直接进入书源管理界面；
   - 进入后提示：`当前没有开启的书源`。

本任务中的“全部开启”只改变搜索页本次使用范围，不批量修改 `book_sources.enabled`。全局书源启停仍由书源管理页负责，避免一次搜索确认意外改写用户的长期配置。

## 2. 现状与根因

Flutter 当前调用链为：

```text
BookSourceGateway.watchAll()
  -> BookSearchCoordinator.watchEnabledSources()
  -> 先过滤 enabled
  -> SearchViewModel.sources
  -> SubmitSearchIntent
```

`SearchViewModel` 只能看到全局已启用书源，因此 `sources.isEmpty` 同时可能表示：

- 数据库没有任何用户可见书源；
- 有书源，但全部被全局关闭；
- 成人内容可见性策略使当前可管理书源为空。

搜索页自己的范围则由 `useAllSources`、`selectedSourceUrls`、分组、书源搜索词和“仅成功书源”共同决定。当前 `_resolvedSelectedSourceUrls()` 为空时只发出同一条 SnackBar，无法执行用户要求的三路分流。

Android 参考实现已经提供搜索页打开 `BookSourceActivity` 的入口，并会在限定范围无结果时询问是否切回全部范围；本方案沿用其“搜索范围与全局启停分层”的原则，但按当前 Flutter 主界面的 `IndexedStack` 导航结构实现。

## 3. 书源可用性事实

在 `BookSearchCoordinator` 增加只读的搜索书源可用性快照，由现有 `BookSourceGateway.watchAll()` 单次流转换得到：

```text
SearchSourceAvailability
  visibleSourceCount
  enabledVisibleSources
```

- `visibleSourceCount`：书源管理页当前能够展示和操作的书源数量；
- `enabledVisibleSources`：其中 `enabled == true` 的书源列表；
- 搜索页继续只把 `enabledVisibleSources` 暴露为可选择和可执行来源。

判定统一采用“用户可见书源”，与书源管理页保持一致。被成人内容策略隐藏的记录不计入可操作总数，否则可能把用户跳转到一个仍然为空的管理列表。

`SearchUiState` 增加明确事实：

- `visibleSourceCount`；
- `loadingSources` 继续表示首个可用性快照是否已经到达；
- `sources` 仍表示全局已启用且可见的书源。

不在每次点击搜索时额外执行 `getAll()`。书源导入、删除、同步或启停后由现有观察流实时更新，避免重复查询和短暂的新旧状态不一致。

## 4. 提交判定优先级

`SubmitSearchIntent` 先规范化关键字，再按固定顺序处理：

| 优先级 | 条件 | 行为 |
|---|---|---|
| 1 | 书源快照仍在加载 | 不导航、不搜索，提示 `正在读取书源，请稍候` |
| 2 | `visibleSourceCount == 0` | 发出携带提示文本的“打开书源管理” Effect |
| 3 | `sources.isEmpty` | 发出携带 `当前没有开启的书源` 的“打开书源管理” Effect |
| 4 | `_resolvedSelectedSourceUrls().isEmpty` | 在搜索页显示“全部开启”确认框 |
| 5 | 其余情况 | 使用解析后的非空 URL 集合开始搜索 |

该优先级保证：

- “全局全部停用”不会被误判成“搜索页未选择”；
- “搜索页未选择”不会触发书源管理跳转；
- 首个书源快照到达前不会因初始空列表误跳转。

搜索页确认框使用状态而不是一次性 Effect 承载，并保存待继续的规范化关键字，防止用户在对话框显示期间修改输入后搜索了错误内容：

- 标题：`提示`；
- 正文：`当前没有开启搜索书源，是否全部开启`；
- 取消按钮：`取消`；
- 确认按钮：`全部开启`。

确认后一次性执行：

1. `useAllSources = true`；
2. 清空显式 URL 集合；
3. 清空搜索页分组、书源名搜索词及“仅成功书源”限制，确保“全部”确实覆盖当前全部全局已启用且可见书源；
4. 重新解析当前可执行书源；
5. 若书源快照期间发生变化，再按同一优先级复判；
6. 仍有可执行书源时立即继续原提交关键字。

## 5. 跨页面导航与提示

### 5.1 主界面内嵌搜索页

`WelcomeRoute` 中搜索页和书源管理页是同一 `IndexedStack` 的一级页面。内嵌搜索页不得再压入一个重复的 `/book-sources` 路由。

实施方式：

- `SearchRoute` 增加可选的“打开书源管理并提示”回调；
- `WelcomeRoute` 收到回调后把一级目的地切换到索引 `2`；
- 切换完成后的下一帧通过主框架 `ScaffoldMessenger` 展示一次提示；
- 每次提交只产生一次提示，不在书源观察流持续为空时重复弹出。

### 5.2 独立搜索路由

独立 `/search` 没有主框架切页回调时：

- 使用命名路由进入 `/book-sources`；
- 通过类型化路由参数传入一次性初始提示；
- `BookSourceManagementRoute` 首帧完成后显示提示；
- 参数只用于当前路由实例，不写入 ViewModel 或持久化。

从书源管理页返回或切回搜索页后，保活 `SearchViewModel` 继续通过观察流收到最新书源快照，不需要手动刷新。用户启用或添加书源后需再次主动提交搜索，不自动恢复先前被导航中断的请求。

## 7. 性能、生命周期与 UI 约束

- 复用单条书源观察流，不在搜索提交时重复扫描数据库；
- 可用性快照只保存一个数量和已启用列表，不复制完整的未启用书源集合到搜索 UI 状态；
- 当前搜索仍固定启动时书源快照，管理页后续启停只影响下一次搜索；
- `SearchViewModel.dispose()` 继续取消书源订阅，对话框待处理状态随 ViewModel 释放，不持有 `BuildContext`；
- 路由提示只通过一次性 Effect/参数传递，不建立永久全局事件总线；
- 确认框使用 Material 原生过渡；一级页面沿用现有 `IndexedStack`，不新增昂贵动画或重复页面构建。

## 8. 用户验收矩阵

AI 按仓库约定不运行 build、test、analyze、lint、format 或应用启动。代码执行后由用户验证：

1. 删除全部可见书源，从搜索页提交关键字：
   - 自动切到书源管理页；
   - 只提示一次 `当前没有书源，请添加书源`。
2. 导入至少一个书源，并在书源管理页把所有书源关闭，再提交：
   - 自动切到书源管理页；
   - 只提示一次 `当前没有开启的书源`。
3. 至少一个书源全局开启，在搜索书源面板中取消全部选择，再提交：
   - 不离开搜索页；
   - 弹出 `当前没有开启搜索书源，是否全部开启`。
4. 在确认框点击“取消”：
   - 不开始搜索；
   - 原搜索范围保持不变。
5. 再次提交并点击“全部开启”：
   - 搜索页局部范围恢复全部；
   - 自动使用原提交关键字开始搜索；
   - 不改变书源管理页的全局开关。
6. 使用分组、书源名筛选或“仅成功书源”制造零个执行来源：
   - 同样询问是否全部开启；
   - 确认后清除这些局部限制并开始搜索。
7. 在书源管理页新增或启用书源后切回保活搜索页：
   - 无需重建页面即可在下一次搜索中使用新快照；
   - 不自动执行之前被导航中止的搜索。
8. 从独立 `/search` 路由重复以上无书源/全停用场景：
   - 压入独立书源管理路由；
   - 目标页首帧后展示对应提示；
   - 返回后仍保留搜索输入状态。
