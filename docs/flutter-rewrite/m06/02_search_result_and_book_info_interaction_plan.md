# 搜索结果分类与详情操作反馈实施方案

> 创建日期：2026-07-22  
> 范围：Flutter 搜索页键盘收起、搜索结果分类 PageView 与书籍详情页主操作卡视觉反馈。

## 1. 目标与非目标

本次只完成以下三项 UI 行为：

1. 搜索输入框获得焦点且系统键盘已显示时，点击输入框以外任意区域均收起键盘；原点击动作（例如打开结果、切换页签、点击菜单）仍照常执行。
2. 搜索结果按已提交关键字分为“书名”“作者”和可选“其他”三个 PageView 页面。书名或作者包含关键字的结果分别进入对应页面；两者都不匹配的结果进入“其他”。当“其他”为空时，不创建也不显示该页面。
3. 调整书籍详情的四个主操作卡，使可用、进行中、需要前置条件和暂未接入能力具有清晰且不被误判为“系统禁用”的视觉与文案。

不包含：修改搜索协调器、去重键、排序、持久化结构、路由、Android 原工程、阅读记录数据能力或任何网络/规则实现。

## 3. 交互与分类规则

### 3.1 键盘

- 在搜索 `TextFormField` 上使用 `onTapOutside` 统一调用当前焦点的 `unfocus()`。
- 不包裹全页手势层，避免与结果卡、菜单、滚动和 TextField 自己的手势竞争。
- 点击输入框本身不收起键盘；点击输入框之外的任何命中控件会先取消输入焦点，再继续其原有动作。

### 3.2 PageView 分类

- 比较值为 `committedKeyword.trim()` 与书名、作者的去空白文本；使用不区分大小写的包含匹配。
- 书名匹配优先归入“书名”；若书名不匹配而作者匹配，则归入“作者”。这保证同一去重结果不会在多个 PageView 重复出现。
- 两者都不匹配的结果归入“其他”；常见原因包括书源返回的相关书、分类词或非标题/作者命中结果。
- “其他”结果为空时，仅创建“书名”“作者”两个页面；页面数据变化导致“其他”消失时，当前页码会安全回退到有效页。
- PageView 上方提供与页面一一对应的轻量切换栏；每页使用独立 `PageStorageKey` 保存滚动位置。结果卡复用现有封面、来源数量与打开详情 Intent。
- 空分类页显示明确空态，不影响同次搜索的进度、失败摘要、取消和重试入口。

## 4. 详情页操作卡视觉策略

| 状态 | 视觉与交互 |
|---|---|
| 可立即执行 | 保持主色图标、正常对比度、涟漪反馈和可点击语义。 |
| 后台进行中 | 显示进度指示器和“正在加入/切换中”等文案，临时阻止重复触发。 |
| 需数据准备 | 采用中性边框或低强调容器，不使用禁用灰；显示如“目录加载中”“加载目录后可阅读”的原因文案。 |
| 业务尚未接入 | 保持可点击，触发现有明确提示，不伪装为成功，也不让用户误以为按钮损坏。 |
| 永久不可用（例如本地书无换源） | 仅这一类使用真正的禁用语义与弱化色，并给出原因。 |

操作卡会继续维持稳定最小触控尺寸，避免状态切换时布局跳动；不新增动画控制器或长生命周期对象，从而避免额外资源释放负担。

## 6. 用户验收建议

1. 在搜索框输入关键字并让键盘弹出，分别点击空白处、历史词、筛选、结果项与分页切换栏，确认键盘收起且原操作仍执行。
2. 使用同时命中书名、仅命中作者及两者都不命中的结果，确认归类符合规则且同一结果不重复；没有“其他”时确认第三页不存在。
3. 在详情页分别检查加入书架、目录、换源和阅读记录：可用项有明确可点击反馈，加载/前置条件/未接入项能说明原因，不再像无故禁用。
4. 反复切换搜索结果页和详情状态，确认列表位置、页面切换和操作卡高度稳定。

AI 不运行 build、test、analyze、lint、format 或应用启动；验证由用户执行。
