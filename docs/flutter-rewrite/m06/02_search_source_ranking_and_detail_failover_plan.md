# 搜索候选书源排序与详情目录自动回退方案

状态：`IMPLEMENTED_PENDING_VERIFICATION / 待用户运行验证`

静态盘点日期：2026-07-23

## 目标

减少用户从搜索结果进入书籍详情后，因首选书源目录加载失败而必须手动切换同组书源的次数；不改变书名与作者的分组合并语义，不预先把搜索阶段扩展成目录抓取任务。

## 当前事实

1. `SearchViewModel._merge` 已将同名同作者的 `SearchBook` 聚合为 `BookSearchResultGroup`，候选列表排序规则已经是“用户置顶优先、其余按 `sourceScore` 降序”。搜索列表点击 `group.primary`，详情页同样以该候选作为初始来源。
2. `sourceScore` 是书源级的累计分值：搜索成功加 1；详情目录成功加 1；详情目录失败减 1。`SearchBook` 保存的是搜索解析时的分值快照，因此新书源、分数相同的书源，或刚发生目录失败后的当前搜索结果，不能仅靠现有排序保证目录可用。
3. `BookInfoViewModel` 当前在目录失败后只记录失败分值和错误状态；同组其他候选仍在路由参数中，但必须由用户手动触发切换。
4. 原生 Android 有阅读阶段“自动换源”设置，但这不等于在搜索列表中预取所有目录；Flutter 当前详情页尚未实现同组候选的目录失败自动回退。

## 方案选择

采用“历史排序 + 详情页受控自动回退”，不在搜索页自动获取目录。

| 方案 | 结论 | 原因 |
|---|---|---|
| 搜索页为所有结果预取目录 | 不采用 | 请求量会扩大为“结果数 × 同组来源数”；拖慢首屏、浪费流量、增大内存和取消管理复杂度，也更易触发书源限流。 |
| 仅继续使用当前历史成功率排序 | 不足 | 已有该逻辑，但无法处理同分、新书源与当前书籍级目录失效。 |
| 首选候选失败后，详情页顺序尝试同组剩余候选 | 采用 | 只为用户明确打开的单本书产生额外请求；能够直接解决目录失败后的手动切换成本。 |

## 拟定行为

1. 搜索候选维持排序优先级：用户置顶、历史 `sourceScore`、原始书源排序值、书源 URL 字典序。新增后两项仅用于同分时保证稳定，不改变用户置顶意图。
2. 用户点击搜索结果后，详情页先请求 `group.primary` 的详情和目录。
3. 若详情或目录加载失败，且该书尚未加入书架、当前搜索组仍有未尝试候选，则按既有候选顺序串行尝试下一个来源。
4. 任一候选取得有效目录后立刻停止回退，更新 `selectedBook`、详情、目录与成功率；页面提示“已自动切换到可用书源”。
5. 全部候选失败时才展示最终错误，并保留“换源”入口和每次失败对应的书源扣分。
6. 用户主动换源、页面退出、新搜索世代或取消请求时，停止自动回退链，沿用现有 generation 与 cancellation token 语义，禁止旧请求回写页面。
7. 已在书架的书不自动替换来源，避免未确认的书籍主键、目录和阅读进度迁移；仍走既有整书换源流程。

## 实施边界

涉及 `SearchViewModel`、`BookInfoViewModel`、搜索/详情 Contract 与必要的 UI 文案；不改变数据库 Schema，不增加依赖，不在搜索结果列表建立目录缓存，也不修改 Android 参考工程。

## 预期验收

1. 多个同名作者候选中，置顶来源优先；未置顶候选按分数降序，分数相同保持稳定顺序。
2. 首选来源详情或目录失败、第二候选成功时，详情页自动显示第二候选的详情与目录，用户无需手动切换。
3. 所有候选失败时显示明确失败状态，不产生并发的多来源目录请求。
4. 已加入书架的书发生目录失败时不自动替换书源。
5. 退出详情页或开始新搜索后，旧回退请求不再更新 UI。

## 实施记录

2026-07-23 已写入首批实现，尚未由 AI 运行或检查：

1. `SearchViewModel` 保留“置顶、成功率”的既有优先级，并为同分候选补充 `originOrder`、书源 URL 和书籍 URL 的稳定排序。
2. `BookInfoViewModel` 在未入书架的详情或目录请求失败时，按候选组顺序串行切换到下一个未尝试候选；任一候选取得目录后停止并提示用户。
3. 用户主动重试或主动换源会重置本轮候选尝试记录；已入书架书籍不参与自动回退。
