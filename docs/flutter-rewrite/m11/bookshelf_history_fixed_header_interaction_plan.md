# 书架与历史固定顶部交互调整方案

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`

## 本次目标

调整书架目的地内的“书架 / 历史”双页交互：顶部标题、页签和右上角操作栏固定不随横向手势移动；仅顶部以下的筛选/搜索区与内容列表可左右滑动切换。页签选中背景与手势进度联动，并将控件改为无半圆描边的矩形样式和自下向上渐隐的背景渐变。

本次还会统一右上角三项操作入口，并按当前页分发：书架页继续执行导入、本页布局切换和目录刷新；历史页不执行书架刷新或布局切换，而是对不适用操作给出明确且短暂的提示，避免错误修改历史数据。刷新运行结束后，状态区保留“关闭”按钮，用户可主动收起刷新结果、进度和失败摘要。

## 现状与原因

- `BookshelfRoute` 当前把 `BookshelfScreen` 和 `ReadingHistoryScreen` 直接作为 `PageView` 的两个子页；两个页面各自创建 `AppBar`，所以顶部会跟随内容横移。
- `BookshelfPageSwitcher` 使用 Material `SegmentedButton`，默认外观包含圆角分段边界，无法满足矩形、渐变背景和进度联动的视觉要求。
- 右上角三项操作目前仅存在于书架页；历史页没有对应入口。
- 刷新结束后，书架状态会持续保留刷新进度和失败列表；当前只能在刷新中点击“停止”，没有收起已完成结果的动作。

## 实现边界

仅改 `ui/bookshelf/` 的页面容器、展示组件与已有书架 UI 状态；不改数据库 Schema、历史快照数据、阅读入口、刷新协调器网络行为或路由参数。

历史页仍只读，不新增删除、筛选、搜索或批量管理能力。右上角三个图标会保持可见性一致，但会根据当前页判断操作是否适用；不适用时显示“历史页暂不支持此操作”的反馈。

## 目标结构

```text
BookshelfRoute
├─ 固定顶部：书架/历史页签 + 右上角三个操作
│  └─ PageController.page 的 0.0..1.0 进度驱动页签背景位移
└─ Expanded PageView
   ├─ 书架：筛选、排序、刷新状态、书籍列表/网格
   └─ 历史：历史书籍列表
```

顶部的 `PageController` 监听器只更新轻量级页签动画状态，不复制书架或历史的列表数据；控制器、监听器和 ViewModel 订阅继续在路由 `dispose` 时释放。

## 交互细则

1. 点击页签使用现有 220ms 动画切页；横向拖动时，固定顶部不移动，仅页签的选中背景按 `PageController.page` 的百分比从“书架”滑向“历史”。
2. 页签容器使用直角矩形，不使用半圆描边；其背景采用当前主题中现有容器色作为底色、向上透明的线性渐变。文字和图标维持可访问的对比度。
3. 从书架滑向历史时，继续立即退出书架选择模式；主导航隐藏书架时也继续退出选择模式。
4. 右上角始终显示导入、布局/列表、刷新三个入口。书架页分别调用既有导入、布局切换、刷新/停止 Intent；历史页点击布局或刷新时显示不支持提示，导入继续打开既有本地书导入流程。
5. 刷新进行时第三项图标仍为停止；完成、取消或失败后，刷新状态区显示“关闭”按钮。关闭只清理本轮展示状态（进度、失败摘要、取消标记），不取消已完成的刷新结果，也不影响数据库中已更新的书籍。

## 用户验收

1. 在书架和历史间横滑，顶部标题、页签和右上角三个图标保持位置不动，只有下面区域切换。
2. 拖动过程中，页签背景连续跟随手势进度滑动；控件为直角矩形，背景从底部主题色向顶部透明渐变。
3. 两页都有三个右上角图标；书架页操作正常，历史页不适用的布局/刷新操作会给出明确提示且不会刷新书架。
4. 书架刷新完成、取消或出现失败后，点击“关闭”可收起刷新结果区；已完成的书籍更新和失败结果之外的页面数据不受影响。
5. 书架选择模式后滑到历史、点击历史或离开主导航，再回到书架时不保留选择。

## 风险与约束

- 不运行构建、测试、分析或格式化；由用户执行验证。
- 不新增依赖，不改变持久化数据，因此不涉及 Schema 或应用构建号变更。
- 动画状态只订阅一个 `PageController`，避免在拖动期间重建或缓存整页列表，降低掉帧和内存保留风险。
