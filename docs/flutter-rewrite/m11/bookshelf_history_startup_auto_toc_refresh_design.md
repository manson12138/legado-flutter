# 书架与阅读历史启动自动更新目录设计

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`。

本文记录 2026-07-27 的静态设计与实施边界，并于 2026-08-02 增加目录增量检查点；按仓库约定未运行编译、测试、分析、格式化或应用。

## 1. 目标

游客或已登录用户打开 App 后，在不阻塞会话恢复、启动遮罩和主界面首屏的前提下，自动联网更新当前本地作用域书架与阅读历史中的网络书目录。书架和历史中相同 `bookUrl` 只请求一次，并分别回写两套独立快照。

书籍详情页同时提供明确可见的“更新目录”操作，用户可以立即刷新当前来源的详情与完整目录。

## 2. 启动顺序

```text
恢复会话并确定游客或账号作用域
  -> 本地书架、分组、历史首快照预加载
  -> 默认书源初始化与下载队列恢复
  -> 主界面已可正常使用
  -> 后台自动目录更新
       -> 合并书架与历史快照
       -> 按 bookUrl 去重
       -> 过滤本地书和 canUpdate=false 的书
       -> 30 分钟内已成功更新则跳过
       -> 从上次分页锚点只跟随新增页；异常时回退完整目录
       -> 固定两个 worker 联网刷新
       -> 书架结果写回 books/book_chapters
       -> 历史结果写回 reading_history_books/reading_history_chapters
```

本地首快照预加载器本身仍然不联网。自动目录更新是后续独立任务，不被 `await` 到启动关键路径。

## 3. 数据一致性

- 书架与历史继续使用独立持久化快照，不因为刷新历史而把书加入书架。
- 同一本书同时存在于书架与历史时只请求一次目录；书架保存刷新结果，历史保存相同目录并保留历史快照自己的阅读章节、字符位置和最后阅读时间。
- 每次运行捕获当前游客或账号作用域 ID 和代次。登录、退出、切换账号或应用根节点销毁时取消全部 HTTP 请求；每次数据库写入前再次核对作用域。
- 单本失败不影响其他书籍；单本请求最长 60 秒。启动后台刷新关闭逐页 `BOOK_TOC` 请求、规则、响应和解析日志，只保留脱敏后的启动阶段摘要与单本失败类型；用户主动刷新仍保留目录诊断日志。

## 4. 性能与资源边界

- 固定最多两个并发 worker，避免启动后同时占满网络、规则引擎和 SQLite。
- 任务只保存待刷新书籍的轻量引用和当前活动取消令牌；完成、取消后立即释放。
- 数据库提交继续通过已有 Repository/UseCase 触发表变化通知，已打开的书架和历史页面无需额外轮询即可收到更新。
- 不持有 `BuildContext`、页面回调或 UI 生命周期对象，避免后台任务造成页面泄漏。

### 4.1 增量目录检查点

- SQLite Schema v11 新增 `toc_refresh_checkpoints`，以 `(userId, bookUrl)` 为主键保存书源、目录入口、
  分页锚点、最多 100 个已访问页地址、末章地址、章节数量、最近成功时间和最近完整校准时间。
- 正序目录从上次最后一页开始，倒序目录只检查上次第一页。分页规则若返回全部页码链接，会用已访问页集合
  过滤旧页，只跟随此前未见过的新页，避免从尾页再次跳回第一页。
- 增量页必须以本地已有章节开头形成稳定重叠；合并后重新生成连续索引。找不到重叠、章节数量倒退、
  正反序变化、书源或目录入口变化、检查点损坏以及网络/规则异常都会自动回退完整刷新。
- 同一账号最近 30 分钟成功刷新过的书启动时跳过；每 7 天强制完整刷新一次，校准章节删除、重排和旧页修改。
- 检查点只在书架和历史快照都保存成功后写入；应用中断时最多丢失优化状态，不会让半成品检查点掩盖旧目录。
- 当前用户已不在书架或历史中的检查点在下次启动任务合并快照后清理。游客与每个登录账号继续完全隔离。
- 首次升级到 v11 没有旧检查点，因此第一轮仍执行完整刷新并建立基线；随后启动才进入节流或增量路径。
- 本次 Schema `10 -> 11`，`pubspec.yaml` build number `11 -> 12`，既有书架、历史和目录数据不重建、不删除。

## 5. 详情页更新入口

- 详情主操作区使用“更新目录”替换原“后续能力”占位卡。
- 更新期间卡片显示工作状态并禁止重复点击。
- 操作复用已有 `BookInfoMenuAction.refresh`，执行请求前脚本、重新加载详情和完整目录；当前书已入架时继续原子替换持久化目录。
- 本地书不提供联网更新。

## 6. 用户验收

1. 为书架网络书准备网页端新增章节，冷启动 App 后等待后台任务完成，确认书架最新章节和未读数自动变化。
2. 对仅存在于阅读历史、不在书架的网络书重复上述步骤，确认历史快照目录更新且不会自动加入书架。
3. 同一本书同时位于书架和历史时，确认两边目录都更新，历史阅读位置不回退。
4. 将书籍设为“禁止更新”或使用本地书，确认启动自动更新跳过该书。
5. 自动更新期间退出登录或切换账号，确认旧账号结果不会写入新账号。
6. 在详情页点击“更新目录”，确认按钮显示更新状态、不会重复触发，并在完成后展示最新章节。
7. 升级后的首次冷启动等待完整刷新完成；30 分钟内再次冷启动，确认完成日志中的 `skippedFresh` 等于可更新书数。
8. 30 分钟后为多页目录增加章节并冷启动，确认 `incremental` 增加且只请求旧尾页和新增页；破坏检查点页后确认 `fallback` 增加并仍能完整更新。
9. 将检查点完整校准时间调整为 7 天前后冷启动，确认该书进入 `full` 而不是增量路径。
