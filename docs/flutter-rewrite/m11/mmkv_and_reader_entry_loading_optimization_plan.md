## 1. 已确认决策

1. 项目引入腾讯/微信官方 Flutter MMKV 包，目标版本为 `mmkv: ^2.4.0`。
2. 接受 MMKV 2.x 不支持 Android 32 位架构的边界，Android 交付只要求 64 位。
3. MMKV 用于小型、独立、高频读取、无需关系查询和事务的持久化偏好。
4. SQLite 继续负责关系数据、列表数据、事务、条件查询、任务队列、带业务一致性的状态和大正文缓存。
5. Token 继续使用 Keychain/Keystore，Cookie、密码和授权信息不得写入普通 MMKV。
6. 先完成 MMKV 基础设施和第一批偏好迁移，再实施阅读器无通用 loading 进入。
7. 阅读器文本正文入口使用最长 300 毫秒专用转场；动画只覆盖短本地读取，不代替缓存和关键链优化。
8. 第一次打开一本书显示有业务内容的先导页；重复进入不显示首次先导页。

## 2. 当前持久化用途清单

### 2.1 首批迁移到 MMKV

以下状态体积小、读取频繁、没有列表事务或关系约束，适合第一批迁移：

| 当前状态 | 当前位置/键 | MMKV 新键建议 | 迁移原因 |
|---|---|---|---|
| 阅读器全局显示配置 | SQLite `reader:config:global` | `reader.display_config.v1` | 每次进入阅读器都需要，字段整体是小 JSON |
| 书架布局 | SQLite `bookshelf_layout_mode` | `bookshelf.layout_mode.v1` | 单个枚举 |
| 阅读历史布局 | SQLite `reading_history_layout_mode` | `reading_history.layout_mode.v1` | 单个枚举 |
| 搜索匹配方式 | SQLite `search_match_mode` | `search.match_mode.v1` | 单个枚举名称 |
| 搜索期用户交互开关 | SQLite `setting_search_source_interaction` | `search.source_interaction.v1` | 单个布尔值 |
| 下载并发上限 | SQLite `setting_download_maximum_concurrency` | `download.maximum_concurrency.v1` | 单个受控整数 |
| 首次阅读先导页状态 | 当前不存在 | `reader.intro_seen.v1:<userId>:<bookDigest>` | 新增的小型用户级版本标记 |
| 阅读器工具栏自动展示状态 | 旧实现仅为进程内静态标记 | `reader.menu_auto_shown.v1.device` | 设备安装周期内只自动展示一次的布尔值 |
| 匿名埋点授权 | SQLite `remote_app_analytics_consent_v1` | `privacy.analytics_consent.v1` | 每次埋点都会读取的设备级布尔值 |
| 成人内容屏蔽开关 | SQLite `flutter_adult_content_blocking_enabled` | `content_filter.adult_blocking_enabled.v1` | 单个设备级布尔值，规则正文仍留 SQLite |
| 已读公告 ID | SQLite `remote_app_read_announcement_ids_v1` | `remote_app.read_announcement_ids.v1` | 小型集合 JSON，限制最多 500 项 |

以上共十组十一个键。阅读显示配置、首次先导页状态和工具栏一次性展示状态直接服务于阅读器体验；匿名埋点授权从每次事件的
SQLite 查询改为进程内值加 MMKV；其余设备级偏好统一走同一基础设施。

`reader.menu_auto_shown.v1.device` 的语义固定如下：

- 作用域：当前设备上的本次 App 安装，不按游客、登录账号或书籍隔离；
- 默认与损坏值：键不存在或无法读取为布尔值时按“尚未展示”处理；
- 迁移：v1 没有旧持久化来源，旧进程级静态标记不能跨进程证明已展示，升级后允许实际展示一次再落键；
- 提交时机：阅读正文与顶部/底部工具栏已经实际进入可见帧后写入，先导页或加载失败不会提前消耗；
- 删除与失效：退出登录、切换账号、清理书籍和覆盖安装均不删除；卸载 App、清除应用数据或未来显式升级键版本时重置；
- 降级：MMKV 初始化失败时使用既有进程内 Store，本进程不重复展示，下次冷启动重新尝试持久化；
- 隐私：只保存布尔值，不包含账号、书籍 URL、书名、阅读进度或正文。

### 2.2 后续单独评估迁移

以下数据表面上属于 KV，但存在额外一致性语义，不放入本次首批：

|---|---|

| 远端书源同步游标 | 属于可恢复检查点，不是普通 UI 偏好 |

### 2.3 必须保留 SQLite 或现有安全存储

| 数据 | 保留位置 | 原因 |
|---|---|---|
| 书籍、目录、分组、书架 | SQLite | 关系、排序、用户作用域和事务 |
| 阅读历史、进度、稳定锚点 | SQLite | 与书籍、章节、换源和账号作用域保持一致 |
| 书签、正文标注、替换规则 | SQLite | 列表查询、排序、筛选和事务 |
| 下载任务与自动换源状态 | SQLite | 崩溃恢复、任务状态机和批量更新 |
| 原始章节正文缓存 | SQLite，后续可单独评估文件缓存 | 内容大、带有效期和批量删除 |
| 封面 URL 缓存 | SQLite | 键数量随书籍增长，带查找和清理语义 |
| JavaScript `cache` API、书源变量、登录头 | SQLite | 脚本可见兼容行为和有效期语义不能改变 |
| 埋点/书源成功率待发送队列 | SQLite | 顺序、幂等、容量、批量和崩溃恢复 |

| Cookie、Authorization、密码 | 现有 Cookie/安全边界 | 禁止进入普通偏好 |

本次不会删除 `caches` 表。它仍承担正文缓存、脚本兼容缓存、队列和远端状态等职责。

## 3. MMKV 基础架构

### 3.1 初始化链

官方 MMKV 要求访问实例前先完成 `MMKV.initialize()`。结合当前首帧后创建完整组合根的架构，目标链路为：

```text
runApp(PageNestBootstrapApp)
  -> Flutter 轻量首帧
  -> 单飞 await MMKV.initialize()
  -> 创建单进程 legado.preferences 实例
  -> 创建 AppPreferencesStore
  -> 创建正式 AppDependencies
  -> 进入 PageNestApp
```

约束：

- 不把 MMKV 初始化放回 `runApp()` 之前；
- 初始化失败时使用进程内偏好降级实现，并允许从 SQLite 旧值恢复，不让 App 永久卡在启动页；
- 初始化任务必须单飞；
- 日志不记录 MMKV 根目录、文件路径、偏好值或用户输入；
- 使用默认单进程模式，不为每本书创建 MMKV 文件。

### 3.2 项目内抽象

业务代码不直接依赖 `package:mmkv`，增加窄接口：

```text
AppPreferencesStore
  -> contains
  -> readBool / readInt / readDouble / readString
  -> writeBool / writeInt / writeDouble / writeString
  -> remove
```

实现：

- `MmkvAppPreferencesStore`：正式 Android/iOS 实现；
- `MemoryAppPreferencesStore`：初始化失败时的进程内降级；
- 各 Feature 使用类型化包装，不直接拼 key：
  - `ReaderDisplayConfigStore`
  - `ReaderIntroPreferences`
  - `BookshelfLayoutPreferences`
  - `SearchPreferences`
  - 搜索交互设置的类型化 Store
  - 下载并发设置的类型化 Store

MMKV、MMBuffer 或原生实例不得进入 Widget、ViewModel、UseCase 和领域模型。

### 3.3 值与作用域

- 设备级偏好使用固定稳定键；
- 用户级偏好带 `userId` 前缀；
- 阅读器先导页使用当前用户 ID 和不可逆 `bookUrl` 摘要，不存原始 URL；
- 阅读显示配置是设备级，全账号共用；
- 首批值使用基本类型或小 JSON；
- 不使用 MMKV 保存大正文、图片、分页结果、Widget 或控制器。

## 4. SQLite 到 MMKV 的兼容迁移

### 4.1 迁移原则

每个类型化 Store 独立迁移，不能把整个 `caches` 表批量搬入 MMKV：

1. 先读取 MMKV 新键；
2. 新键存在则不再查询 SQLite；
3. 新键不存在时读取对应 SQLite 旧键；
4. 校验并归一化旧值；
5. 成功写入 MMKV 后记录该项迁移版本；
6. 失败不写完成标记，下次允许重试；
7. 首个迁移版本保留 SQLite 旧记录，不主动删除；
8. 迁移完成后的正常读取和写入只走 MMKV，避免长期双事实源；
9. MMKV 值损坏时使用受控默认值并允许重写，不回退读取可能已经过期的 SQLite 旧值。

### 4.2 阅读显示配置

- 抽取现有 JSON 编解码为纯 Dart codec；
- MMKV 保存完整版本化 JSON，而不是逐字段跨 FFI 读取；
- `ReaderDisplayConfigStore` 初始化后持有不可变同步内存值；
- 设置页面只更新草稿；沿用最终提交时机写 MMKV，不能在 Slider 每一动画帧写入；
- SQLite 旧按书籍键只在全局旧键也不存在时执行一次兼容迁移；
- 换源不再“复制全局显示配置”，但单书 `ReadConfig` 等 Android 业务字段仍保持原有语义。

### 4.3 先导页状态

建议键：

```text
reader.intro_seen.v1:<userId>:<sha256(bookUrl)>
reader.menu_auto_shown.v1.device
```

规则：

- 第一次真正进入正文页后标记为已看过；
- 只打开先导页后立即返回，不写已看过，下次仍展示；
- 正文加载失败不写已看过；
- 换源产生新 `bookUrl` 时视为新的阅读身份，可再次展示；
- 账号切换使用不同用户前缀，不互相影响；
- MMKV 丢失只会让先导页再次出现，不会影响阅读进度。

## 5. 阅读器当前 loading 关键链

当前文本阅读器有两层通用转圈：

```text
BookReaderRoute FutureBuilder
  -> 再查书籍并等待 PDF/文本分流
  -> 圆形 loading

ReaderRoute / ReaderViewModel
  -> 初始 content=null
  -> ReaderScreen 圆形 loading
  -> 串行查书籍、目录、显示配置、锚点、旧进度
  -> 读取原始正文、替换规则并重新处理
  -> content ready
```

即使原始正文命中 SQLite，页面生命周期独占的处理后正文 LRU 也会在退出时清空，下一次进入仍要重新处理。
显示配置迁移 MMKV 能删除一项等待，但不能单独消除全部 loading。

## 6. 阅读器目标体验

### 6.1 统一要求

- 文本阅读器进入路径不再展示通用 `CircularProgressIndicator`；
- PDF 阅读器加载不在本专项范围内；
- 最长 300 毫秒转场结束时：
  - 处理后正文已就绪：直接显示正文；
  - 第一次打开：显示首次先导页；
  - 重复打开但正文未就绪：显示简化恢复页；
- 慢网络和规则失败显示书籍信息、错误摘要与重试，不出现无限转圈；
- 返回始终可用。

### 6.2 首次先导页

首次先导页作为阅读器第 0 页：

- 上半部分：封面、书名；
- 中部：作者、目标章节标题、章节序号、总章节数、书源；
- 下半部分：自定义简介优先，其次书源简介；
- 正文未就绪时显示轻量状态文案，不显示圆形进度；
- 正文未就绪时正文方向滑动不移动，并节流提示“章节正在准备，完成后即可阅读”；
- 正文就绪后开放向正文方向滑动，同时显示“开始阅读”按钮；
- 第一次实际显示正文时写入 MMKV 先导页已看标记，并沿用现有历史/埋点成功语义；
- 封面网络加载独立进行，失败只显示占位，不阻塞正文。

不设置强制最短展示时间。如果正文很快准备完成，用户可以立即滑动或点击开始阅读。

### 6.3 重复进入恢复页

- 处理后正文内存命中：转场结束直接显示上次字符锚点；
- 只有原始正文缓存：在转场期间后台处理，300 毫秒内完成则不展示恢复页；
- 超过转场仍未完成：显示封面、书名、目标章节和“正在恢复阅读位置”文案；
- 正文首个可读页完成后自动短淡入，不要求用户再次点击；
- 错误时在同一恢复页显示“重试/返回”。

## 7. 阅读器优化链路

### 7.1 路由复用现成 Book 快照

当前书架和历史 Effect 已经持有 `Book`，但只向阅读器传 `bookUrl`。修改后：

- 书架、历史和详情入口统一传 `Book` 快照；
- 详情继续传完整目录快照；
- 路由参数携带明确的书架成员事实；
- `BookReaderRoute` 直接使用快照区分 PDF/文本；
- 只有旧字符串路由、快照缺失或主键不匹配时才查数据库；
- 文本 ViewModel 不重复查询同一本书。

数据库仍是后续写入的最终事实，路由快照只优化进入首帧。

### 7.2 同步建立阅读壳

Reader ViewModel 创建时立即具备：

- `Book` 快照；
- MMKV 内存中的 `ReaderDisplayConfig`；
- 是否首次阅读；
- 已知章节标题、索引、总数、封面和简介；
- 默认先导页或恢复页状态。

因此路由转场第一帧已经能画出正确阅读背景和有业务内容的页面，不等待 SQLite。

### 7.3 并行本地初始化

在书籍事实确定后并行执行：

- 目录读取（没有路由快照时）；
- 稳定锚点；
- 旧阅读进度；
- 当前章节原始正文缓存探测。

显示配置不再进入 Future 链。目录、锚点和进度结果发布前继续核对当前用户、路由和加载世代。

### 7.4 首显关键链收窄

正文首显前只等待：

- 目标章节；
- 最终显示配置内存值；
- 当前章处理后正文；
- 稳定字符锚点；
- 当前模式首个可读页面。

以下工作延后且不得重新触发全页 loading：

- 书签和正文标注订阅；
- 完整替换规则列表；
- 相邻章节预加载；
- 电量/时间；
- 阅读历史落库和匿名埋点；
- 非当前章节目录刷新、下载状态和封面补全。

## 8. 应用级处理后正文 LRU

### 8.1 职责

网络令牌、预加载 worker 和页面状态仍属于页面独占协调器；只把纯
`ReaderChapterContent` 缓存提到应用级。

缓存键包含：

- 用户 ID；
- `bookUrl + chapterUrl`；
- 替换规则开关及失效代次；
- 简繁转换模式；
- 重新分段开关；
- 正文原始缓存版本或显式失效代次。

字号、行距和边距只使分页缓存失效，不需要重新处理原始正文。

### 8.2 内存边界

- 最多三章；
- 同时设置估算字节上限，防止三个超长章节无界占用；
- 不持有 Widget、BuildContext、Controller、Stream、Timer、平台对象和取消令牌；
- 内存压力、账号切换、整书/单章换源、强制刷新、删除离线正文和替换规则变化时清理对应项；
- 不把处理后正文持久化到 MMKV。

### 8.3 最近阅读预热

作为第二轮优化：

- App 主界面完成后，只预热最近阅读一本书的当前章；
- 只允许命中现有原始正文缓存；
- 启动预热绝不发书源网络请求；
- 用户发起前台正文任务时立即让路或取消；
- 成功结果写入同一个三章 LRU。

代码状态：D3 已接入，等待用户验证。主界面进入可交互状态后的下一帧才启动一次当前用户作用域单飞任务，
先复用阅读历史首快照选择最近一本书，再读取其历史目录和当前可读章；PDF、本地原始正文缓存未命中及
空正文都立即结束，不调用书源网络、本地书解析器或前台正文协调器。原始正文命中后才读取最终显示配置和
本地替换规则，并在可取消 isolate 中完成净化、转换、替换和分块，成功结果写入同一三章/约 4 MiB LRU。
前台可见章节开始加载会永久关闭当前作用域的启动预热并立即终止正在运行的处理 isolate；账号切换允许
新作用域重新预热，系统内存压力和应用销毁会取消且释放任务。所有 SQLite/isolate 晚到结果在写入前同时
核对用户 ID、用户代次、任务代次和取消状态。

### 8.4 卡顿与主线程硬约束

- 阅读入口转场只允许驱动封面隔离层的 `Transform`、`Opacity` 和必要裁剪，不允许动画每帧触发整页
  布局、全屏重绘、数据库/MMKV 写入或大对象分配；
- 移动中的封面使用局部 `RepaintBoundary`，不制作全屏截图、不使用实时模糊，也不在转场期间重新下载或
  重复解码同一封面；
- Widget `build()` 只消费已经形成的不可变状态，不执行数据库、文件、网络、正文解析、复杂正则、分页或
  章节对象批量转换；
- 正文解析、替换和长章分页不得占用动画关键帧；可并行的本地读取先启动，重处理按现有 isolate/协调器边界
  执行，非首显工作延后到正文首个可读页面提交之后；
- 相邻章节预加载必须低优先级、有界并发，并在当前章节任务到来时让路；失败不得改变当前章节状态；
- 滑动阻断提示采用时间节流，不能在连续手势事件里反复创建 Snackbar、Overlay 或字符串对象；
- 阅读显示配置只在用户最终提交时写 MMKV，Slider 拖动和转场动画帧只更新内存草稿；
- 快速重复点击书籍入口必须单飞或拒绝重复导航，旧路由、旧书籍和旧章节异步结果必须用世代校验丢弃。

### 8.5 内存与资源释放硬约束

- 处理后正文 LRU 同时受“最多三章”和“估算正文不超过约 4 MiB”双边界约束；单章超过上限时允许当前
  页面显示，但退出当前章后不保留在应用级 LRU；
- 缓存只持有纯 `ReaderChapterContent` 数据，不得持有 Widget、`BuildContext`、`GlobalKey`、
  `ScrollController`、`PageController`、`AnimationController`、`RenderObject`、图片位图、
  Stream、Timer、取消令牌或平台对象；
- 账号切换、整书/单章换源、替换/简繁/分段配置变化、强制刷新、离线正文删除和系统内存压力必须使对应
  正文缓存、分页缓存及预加载代次失效；
- 阅读路由释放时必须取消正文请求、预加载、订阅、Timer、图片监听、Overlay 和动画控制器；所有异步回调
  在发布状态前检查 `disposed`、当前用户、路由主键和加载世代；
- 反向封面转场不得长期持有书架卡片或历史卡片的 `GlobalKey`/元素引用；来源卡片已经离屏或被释放时直接
  降级为阅读器中心缩放淡出；
- 应用收到内存压力后立即清理相邻预览和应用级正文 LRU，当前正在显示的正文只保留完成当前页面所需对象；
- 退出保存与反向动画可以并行，但只允许一个关闭流程；两者完成或保存进入受控超时后再弹出路由，避免重复
  Navigator、重复写进度和释放后回调。

## 9. 最长 300 毫秒转场

### 9.1 书架/历史到阅读器

文本阅读器使用专用 `PageRouteBuilder`。书架/历史进入总时长固定不超过 `300ms`，从被点击 cell 的
真实封面位置放大，并从动画首帧开始按先快后慢节奏淡出露出文章：

- `0～200ms`：封面从真实 cell 位置放大的同时按先快后慢节奏淡出，文章从动画首帧开始在封面下方逐步显现；
- `200～300ms`：临时封面层已经移除，只展示完整阅读页面直到路由动画结束；
- 同一本书可能同时出现在书架和历史 `PageView`，每次点击生成独立转场 ID，不直接把 `bookUrl`
  当全局 Hero Tag；
- 快速重复点击期间入口单飞，已有阅读路由创建时忽略后续点击，避免两层封面和两条正文任务；
- 封面缺失、来源卡片离屏或几何信息失效时，降级为阅读器中心占位封面的缩放淡入。

### 9.2 其他入口与反向转场

- 书籍详情到阅读器不叠加封面移动、3D 开书或专用淡入，使用 Flutter 普通 Material 页面转场；
- 搜索到详情使用共享封面放大，不直接跨过详情执行重型阅读器转场；
- 阅读器返回时只执行约 `200ms` 阅读页淡出，不复用可能已经失效的旧来源位置；
- 阅读器内部目录、显示设置、下载和换源继续使用 BottomSheet 或普通页面转场，不套用封面动画；
- 系统“减少动态效果”开启时取消 3D、位移和阴影动画，使用约 `150ms` 淡入淡出。

### 9.3 动画与数据协作

- 动画只覆盖短本地读取窗口，不等待网络，不用强制停留凑满时长；
- 转场期间继续后台准备目录、锚点、进度和正文；`300ms` 结束时按真实状态显示正文、先导页或恢复页；
- 不创建全屏位图快照，不实时模糊，不重新下载或重复解码封面；
- 正文处理继续在后台 isolate/既有协调器边界执行，避免与动画争抢主 isolate；
- 退出保存与反向动画并行启动并保持关闭单飞，避免保存耗时让返回手势显得失效。

## 12. 验收清单

### 12.1 MMKV

1. 从现有 SQLite 版本升级，阅读字号、颜色、翻页、亮度、全屏和边缘返回设置完整迁移。
2. 杀进程重启后六类首批偏好保持。
3. MMKV 已有新键时，首批偏好正常读取不再查询 SQLite。
4. MMKV 初始化失败或值损坏时 App 仍可进入，并使用受控默认值/兼容迁移。
5. Token、Cookie、密码、正文、队列和关系数据没有进入 MMKV。
6. Android 64 位与 iOS 16+ 真机均可初始化和持久化。

### 12.2 阅读器

1. 冷启动后立即打开书籍，文本阅读器不出现通用圆形 loading。
2. 第一次打开显示封面、书名、作者、章节信息和简介。
3. 正文未就绪时滑动不移动，提示节流，返回可用。
4. 正文就绪后滑动和“开始阅读”都能进入正确章节。
5. 只看先导页后返回，下次仍显示；真正进入正文后下次不再显示。
6. 退出后立即重进，最长 300 毫秒转场结束直接恢复上次位置。
7. 仅持久正文缓存命中时尽量被转场覆盖，超时显示恢复页而不是转圈。
8. 无缓存、断网、规则失败时保留书籍信息和重试/返回。
9. 快速打开/返回/切换书籍，旧任务不覆盖新页面。
10. 改变替换、简繁、分段、换源、刷新和删除下载后不复用旧正文。
11. 账号切换和内存压力后 LRU 清理正确，无跨用户正文和内存泄漏。
12. 减少动态效果、屏幕阅读器和大字体下先导页与转场可用。
13. 连续快速开关阅读器、切章和拖动设置后，订阅、Timer、控制器、Overlay 和图片监听数量不持续增长。
14. 超长章节不会进入无界缓存；内存压力后相邻预览和应用级 LRU 被释放，当前页仍可受控显示或恢复。
15. 最长 300 毫秒转场期间没有正文解析、复杂正则、分页、SQLite/MMKV 写入造成的明显掉帧。
16. 主界面稳定后只预热最近阅读一本书的当前章；原始正文未缓存时无书源请求，立即打开阅读页会取消
    后台处理，账号切换、内存压力和应用销毁后没有旧任务晚到回写。
