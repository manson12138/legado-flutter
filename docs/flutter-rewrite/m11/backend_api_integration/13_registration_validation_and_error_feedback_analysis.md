# App 注册输入规则与错误反馈分析

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / REGISTRATION_CONTRACT_CONFIRMED`。注册字段、邀请码和错误响应契约已由用户于 2026-07-25 明确确认；Flutter 本地校验、受控错误映射、键盘避让和焦点自动滚动已写入，等待用户在 Android 后 iOS 验收。未运行 Flutter、Dart、Gradle、Xcode、后端测试、构建、分析、格式化或应用启动。

## 1. 唯一目标与边界

目标：让注册页在提交前明确说明并校验账号、密码和邀请码规则；注册失败时区分字段错误、邀请码错误、账号冲突、密码加密、网络和服务端错误，不再全部显示“请求失败，请检查网络与输入后重试”；软键盘弹出后表单仍可顺畅滚动，并自动保证当前输入框和提交按钮处于可见区域。

本次建议包含：

- 注册账号本地规则与输入框辅助说明；
- 注册密码最低长度说明与本地校验；
- 普通用户与 App `admin` 角色的邀请码有效期和可使用次数说明；
- 远端认证失败到领域失败、再到中文 UI 文案的受控映射；
- 网络失败按 DNS、连接、TLS、超时和服务端状态分类；
- 注册表单的键盘避让、滚动范围、焦点顺序和当前输入框自动可见；
- API 文档补齐注册规则和注册专属错误。

明确不包含：

- 修改 RSA-OAEP-SHA256 密码传输、Token、会话恢复或注册后自动登录语义；
- 记录用户名、密码、邀请码、密文、公钥、Token 或完整认证响应；
- 修改数据库 Schema、路由或书源业务；
- 将未经白名单确认的服务端原始异常直接展示给用户。

## 2. 实施前静态核对结论

用户提供的 `novel-admin-api-selected-2026-07-25 (1).json` 是可正常解析的 UTF-8 JSON，不存在导致注册失败的 JSON 语法问题。文件只导出了注册成功示例和通用 HTTP/业务码，没有写出注册字段约束及注册专属失败原因，因此单靠该文件无法判断某次真实注册为何失败。

实施前 Flutter 注册链路存在三个直接缺口：

1. `authentication_route.dart` 只校验账号、密码和邀请码非空，以及两次密码一致；没有校验账号最低 4 位、允许字符和密码最低 8 位。
2. `RemoteAppApi._executeEnvelope()` 只保留数字业务码和 HTTP 状态，主动丢弃响应 `message`；`AuthenticationViewModel._submit()` 又把绝大多数异常统一转换成“请求失败，请检查网络与输入后重试”。
3. 认证页虽然使用 `ListView`，但根部认证门的嵌入模式只返回 `Material`，没有使用可按键盘 Insets 调整内容区的 `Scaffold`；列表底部 Padding 也没有加入 `MediaQuery.viewInsets.bottom`。当注册表单内容未超过整屏高度时，键盘只覆盖邀请码区域，列表仍认为没有可滚动溢出；页面也没有在焦点切换或键盘尺寸变化后主动将当前输入框滚入可见区域。

因此以下完全不同的失败目前会显示同一句话：

- 账号长度或字符不合法；
- 账号已存在；
- 密码长度不合法；
- 邀请码无效、过期或已经使用；
- 密码加密失败；
- DNS、连接、TLS 或超时；
- 后端 500。

## 3. 用户已确认的注册契约

注册接口使用有效邀请码创建 App 账号。用户已确认的字段和标准化规则如下：

| 字段 | 已确认行为 | 对“空格”的影响 |
|---|---|---|
| 账号 | 去除首尾空白、转小写，然后要求匹配 `^[A-Za-z0-9_]{4,32}$` | 首尾空白会被去除；内部空格、全角字符、中文、横线和点号都会失败 |
| 密码 | 必须为 8～72 位；不得在客户端提交前擅自 `trim` | 首尾和内部空格都会成为真实密码内容；复制时多一个不可见空格也会改变密码 |
| 邀请码 | 必须满足服务端约定格式并处于当前角色对应的有效状态 | 首尾空白和大小写的规范化方式应与服务端实现保持一致；内部空格属于格式错误 |

邀请码按邀请人的 App 角色执行两套明确规则：

- 普通用户生成的邀请码 5 分钟有效，并且只能成功注册一次；
- 普通邀请码在第一个账号注册成功后立即失效；
- 普通邀请码成功消费后，邀请人可以随即生成新的邀请码；
- App 角色为 `admin` 的用户生成的邀请码 1 天有效；
- App `admin` 邀请码在有效期内不限制成功注册人数；
- `admin` 指 App 账号的角色，不应通过用户名是否等于 `admin` 推断；
- 邀请码仍须属于当前产品，邀请人账号和邀请权限必须满足服务端要求。

所以“自己能注册、几个朋友注册不上”不能说明公共网络或 RSA 主链路整体损坏。应先根据邀请码来源判断：

1. 如果邀请码由普通用户生成，多人共用时，第一个成功注册后其他人都会失败；
2. 如果普通邀请码超过 5 分钟，或 App `admin` 邀请码超过 1 天，都会失败；
3. 如果邀请码由 App `admin` 生成且仍在 1 天有效期内，多人注册不应因为成功次数而失败；
4. 账号包含中文、全角字符、横线、点号或内部空格时会失败；
5. 账号不足 4 位、超过 32 位，或大小写不同但标准化后与已有账号冲突时会失败；
6. 密码不足 8 位、超过 72 位，或者复制时带入不可见的前后空格时可能失败；
7. 个别设备仍可能存在 DNS、连接、TLS 或超时。

## 4. 用户已确认的错误响应契约

注册校验失败统一返回：

- HTTP 状态：`400`
- 业务 `code`：`40000`
- `message`：明确区分具体失败原因

必须由稳定 `message` 区分的注册校验错误包括：

- 缺少字段；
- 用户名长度不合法；
- 用户名包含不允许的字符；
- 密码长度不合法；
- 邀请码格式不合法；
- 邀请码无效；
- 邀请码已过期；
- 普通用户邀请码已被成功使用。

用户名在当前产品内重复时返回：

- HTTP 状态：`409`
- 业务 `code`：`40900`
- `message`：`该用户名已被当前产品使用`

客户端不能只看 `40000` 后统一显示“输入有误”，也不能把所有 `40900` 都猜测为用户名重复；必须在注册接口上下文中识别后端约定的稳定 `message`。

## 5. 推荐错误模型

不建议把服务端任意 `message` 原样透传到 UI。由于多个注册校验失败按已确认契约共用 `code=40000`，客户端应采用“HTTP 状态 + 业务码 + 注册上下文 + 稳定 `message` 白名单”的组合映射：

1. `RemoteAppApi` 只读取受控响应信封中的 `code`、HTTP 状态和有限长度 `message`；
2. 注册 API 将已确认的 `message` 精确映射为失败原因枚举；
3. `AuthenticationRepository` 将 API 失败转换为不含响应正文的领域失败；
4. Flutter UI 只展示本地固定中文文案；
5. 未进入白名单的响应不原样展示，只显示安全的状态、错误码和重试建议。

建议用户可见文案：

| 场景 | 文案 |
|---|---|
| 缺少字段 | `注册信息不完整，请填写账号、密码、确认密码和邀请码` |
| 账号规则不合法 | `账号需为 4～32 位，仅支持英文字母、数字和下划线` |
| 账号已存在 | `该用户名已被当前产品使用` |
| 密码长度不合法 | `密码必须为 8～72 位` |
| 邀请码格式错误 | `邀请码格式不正确，请检查后重试` |
| 邀请码无效 | `邀请码无效，请获取新的邀请码` |
| 邀请码过期 | `邀请码已过期，请获取新的邀请码` |
| 普通邀请码已使用 | `邀请码已被使用，请获取新的邀请码` |
| 密码加密失败 | `密码安全处理失败，请重试` |
| DNS | `无法解析服务器地址，请检查网络或 DNS 设置` |
| 连接失败 | `无法连接服务器，请检查网络后重试` |
| TLS | `安全连接失败，请检查系统时间或网络环境` |
| 超时 | `请求超时，请稍后重试` |
| HTTP 500 | `服务器内部错误，请稍后重试` |
| 未知业务错误 | `注册失败（错误码：xxx），请稍后重试` |

## 6. 已实施 Flutter 改动

### UI

已修改 `lib/src/ui/authentication/authentication_route.dart`：

- 账号输入框显示“4～32 位，仅字母、数字、下划线”；

- 保持账号和邀请码首尾 `trim`，不得对密码执行 `trim`；
- 密码若包含首尾空白，给出明确提醒，但不得在用户不知情时删除密码内容。

### 键盘避让与滚动

当前问题不是缺少 `ListView`，而是嵌入式认证页没有让滚动视口跟随键盘可见高度变化。已完成以下调整：

- 根部嵌入模式使用 `Scaffold(resizeToAvoidBottomInset: true)` 承载认证内容，不再只使用不会主动避让键盘的 `Material`；
- `Scaffold` 负责按完整键盘 Insets 缩小视口；列表底部 Padding 根据 `MediaQuery.viewInsetsOf(context).bottom` 是否为零在 36 与 48 之间切换，保留键盘上方安全间距而不重复叠加整段键盘高度；
- 为认证列表持有并释放一个 `ScrollController`，只管理页面局部滚动，不进入 ViewModel；
- 为账号、密码、确认密码和邀请码输入框提供稳定的可见性锚点；
- 焦点切换及键盘 Insets 稳定后的下一帧调用一次 `Scrollable.ensureVisible`，将当前输入框滚到键盘上方，并保留适当上下文而不是紧贴屏幕边缘；
- 账号键盘“下一项”进入密码，注册密码进入确认密码，确认密码进入邀请码，邀请码使用“完成”提交；
- 保持 `ScrollViewKeyboardDismissBehavior.manual`，用户向上滚动查看和修改表单时不应被迫关闭键盘；
- 键盘关闭后恢复正常底部间距，不保留大块空白；
- 登录表单字段较少时仍保持居中或接近原布局，不能为了注册页避让导致登录页顶端出现明显跳动。

滚动动画使用 180ms 和 `easeOutCubic` 缓出曲线。焦点与键盘尺寸变化按帧合并；页面销毁后通过 `mounted` 和已释放的页面资源阻止过期回调继续操作。

### Domain/Data/API

- 在认证领域边界增加不携带敏感数据的失败原因枚举；
- `RemoteAppApi` 按 HTTP 状态、业务码和稳定 `message` 白名单解析注册错误，不保存完整响应正文；
- `AuthenticationRepository` 将业务异常、`UnifiedHttpException` 和密码平台异常转换为领域失败；

- 登录和注册可共享网络/加密错误映射，但注册字段、邀请码和账号冲突文案保持独立。

## 7. 性能、生命周期与隐私

- 本地校验只执行固定长度判断和短字符串正则，不引入异步任务、监听器或额外持久状态；
- 不新增网络重试；注册失败仍由用户显式再次提交，避免重复消费邀请码；
- 不记录输入长度、账号、密码、邀请码或服务端认证正文；
- 键盘避让只新增一个页面级 `ScrollController` 和有限输入锚点，并在 `dispose()` 中释放；不新增会话监听或长期计时器；
- 键盘尺寸变化和焦点变化只合并安排一次下一帧可见性检查，避免在输入法动画期间连续触发滚动和重复布局；
- 不修改现有密码、公钥和 Token 的生命周期。
