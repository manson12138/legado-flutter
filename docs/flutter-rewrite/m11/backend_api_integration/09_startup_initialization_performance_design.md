# 启动初始化分层与首帧性能优化方案

状态：`PARTIALLY_IMPLEMENTED / 等待用户验证`。本方案基于 2026-07-25 的静态梳理；已实施媒体目录首帧后单飞预热、方向请求不阻塞首帧、本地会话快照先放行与远端校验后台单飞执行、文件日志/崩溃报告目录的首帧后延后初始化，以及完整 `AppDependencies` 在 Flutter 首帧后的延后创建。认证最小依赖与登录后业务依赖的进一步拆分、原生启动页视觉统一仍待后续实施；未运行编译、测试、分析、格式化或应用。

## 1. 目标与边界

目标是让冷启动尽快从原生启动页进入 Flutter 可交互界面，并且不得让网络、SQLite、默认书源导入、下载恢复或非必要目录创建阻塞首帧和登录输入。

本方案不改变以下产品和安全语义：

- 未登录用户仍不能进入业务路由。
- Token 仍仅保存于 Keychain / Keystore；密码、Token 和认证正文不写入日志。
- Access 或 Refresh Token 已被服务端以 401 明确拒绝时，必须清理会话并回到登录页。
- 内置书源导入、下载队列恢复和 App 准入检查仍在登录成功后执行，且不并发占用 SQLite。
- 不新增数据库字段、表、平台通道或第三方依赖。

## 2. 当前启动关键路径

```text
原生启动页
  -> WidgetsFlutterBinding.ensureInitialized()
  -> 等待固定方向
  -> 等待文件日志目录
  -> 等待崩溃报告目录
  -> 等待全部媒体缓存目录与临时目录
  -> 同步构造完整 AppDependencies（全部阅读、书源、下载、JS 与远端服务）
  -> runApp()
  -> 首帧后恢复认证会话
       -> Keychain / Keystore 读取
       -> 已有会话时请求刷新 Token 或权限
  -> 认证恢复完成后才移除 Flutter 启动遮罩
  -> 登录成功后：内置书源导入 -> 下载恢复 -> 准入轮询
```

因此首帧前的磁盘操作和完整组合根创建会延长原生空白页；已有会话时，认证门又会把远端权限请求（当前接收超时为 60 秒）纳入启动遮罩时长。

## 3. 初始化分层结论

| 层级 | 工作项 | 当前时机 | 建议时机 | 原因与约束 |
| --- | --- | --- | --- | --- |
| P0：必须在 `runApp` 前 | Flutter binding | 启动前 | 保持 | 平台消息、系统 UI 与插件调用的前提。 |
| P0：必须在 `runApp` 前 | 最小内存错误兜底、控制台日志 | 启动前 | 保持 | 不依赖文件系统，保证极早期异常不会丢失。 |
| P0：应发起但不等待 | 竖屏设置 | 启动前等待 | 发起后不阻塞 `runApp` | 仍尽早请求方向；首次布局可能以系统当前方向出现一次，需真机确认。 |
| P1：首帧后高优先级 | Keychain / Keystore 会话快照读取 | 首帧后 | 保持首帧后，但只等待本地读取 | 未登录用户可立即打开表单；已有会话可立即恢复受控账号快照。 |
| P1：首帧后后台 | 会话权限校验、Token 刷新 | 启动遮罩内等待 | 不阻塞启动遮罩 | 网络失败保留未过期会话；401 才退出。需要受保护操作复用单飞恢复任务，避免使用过期 Token。 |
| P1：首帧后后台 | 文件日志器目录与崩溃报告目录 | `runApp` 前等待 | 后台初始化后切换到文件能力 | 初始化完成前继续用内存/控制台兜底；不允许因目录创建失败阻塞 UI 或导致崩溃。 |
| P1：按需/后台 | 媒体目录、下载中间态目录预建 | `runApp` 前等待 | 首帧后低优先级预热；调用处保留按需兜底 | 封面和下载路径已有异步获取入口，不应让未使用封面/下载的用户等待。需改为单飞，避免多个调用重复建目录。 |
| P2：登录成功后串行后台 | 内置书源导入 | 登录成功后 | 保持 | 必须先于下载恢复，避免 SQLite 竞争；绝不阻塞登录完成后的主界面。 |
| P2：登录成功后串行后台 | 下载任务恢复 | 登录成功后 | 保持 | 依赖数据库且可能启动 worker；仅在导入完成或失败清理后启动。 |
| P2：登录成功后后台 | App bootstrap / 准入轮询 | 登录成功后 | 保持 | 网络不可用不能阻断本地可用界面；管理员跳过规则保持。 |
| P3：按页面进入 | JS 引擎、WebView、扫码、书源详情/正文协调器 | 大部分仅构造 | 保持懒创建 | 不可在启动阶段主动打开数据库、WebView、相机或解析书源。 |

## 4. 推荐目标链路

```text
原生品牌启动页
  -> P0：binding + 内存错误兜底 + 请求方向
  -> runApp(轻量启动壳)
  -> 第一帧：展示 Flutter 启动页，随后创建认证所需最小依赖
  -> 读取安全会话快照
       -> 无会话：立即显示可输入的登录页
       -> 有且未到期：立即显示主界面；后台单飞校验权限/按需刷新
       -> Access 过期但 Refresh 有效：显示主界面和非阻断恢复状态；受保护操作等待同一刷新任务
       -> Refresh 过期或远端 401：清理后显示登录页
  -> 登录成功或本地会话已恢复：串行执行书源导入 -> 下载恢复 -> 准入轮询
  -> 文件日志、崩溃报告、媒体目录在首帧后低优先级完成；失败仅降级
```

当前实现额外保证正式应用组合根内的 Flutter 启动遮罩最少展示 500 毫秒；本地会话读取更快时仅补足剩余时间，网络校验仍不属于该遮罩等待条件。

认证门在启动输入开放时会以新的 key 重建其初始 Navigator Route，防止 Route 缓存首轮 `inputEnabled=false` 而令登录表单永久禁用。启动遮罩使用 220 毫秒淡出，避免与登录页硬切换。

“有会话立即显示主界面”仅适用于本地 Refresh Token 尚未过期的记录。远端校验期间不得把用户重新覆盖为全屏启动页；若最终收到 401，再由会话监听切换到登录门。业务请求应统一等待或复用仓储内部的单飞恢复，而不是各自使用旧 Access Token。

## 5. 推荐实施顺序

1. 引入启动协调器或等价状态机，分离“本地会话快照已判定”和“远端会话校验完成”；启动遮罩只等待前者与认证 Navigator 首帧，而不等待网络。
2. 将 `AuthenticationRepository.restoreSession()` 拆为本地恢复与后台远端校验两个受控入口，保持现有单飞、401 清理、网络失败降级和 Token 安全存储规则。
3. 将 `main.dart` 中文件日志、崩溃报告和媒体目录预热移至 `runApp` 后；为初始化前异常保留内存/控制台兜底，并以可替换的日志/崩溃能力注入方式避免空引用。
4. 将组合根拆成认证启动所需的最小依赖与登录后业务依赖，或至少把不被认证路径使用的重量级创建迁移到主界面后台初始化。数据库、下载、JS 池和书源服务不得在登录页出现前做 I/O。
5. 让 `AppMediaDirectories.warmUp()` 具备幂等单飞语义；首帧后低优先级预热，封面/下载实际使用时继续通过现有异步入口兜底。
6. 统一 Android、iOS 与 Flutter 启动页的背景色和现有品牌图标，消除原生空白页与 Flutter 图标页之间的闪变；不新增设计资产。

## 6. 风险与验收

| 风险 | 防护 | 用户验收 |
| --- | --- | --- |
| 后台恢复完成后旧状态覆盖新登录 | 所有恢复入口复用同一任务；写入前确认当前会话代次。 | 冷启动后立即登录另一账号，确认不会被旧会话覆盖。 |
| Access 过期时主界面提前可见 | 受保护操作等待刷新任务；刷新 401 后统一登出。 | Access 过期 / Refresh 有效时启动、进入受保护入口、刷新成功与 401 各验证一次。 |
| 文件能力尚未就绪 | 内存/控制台兜底，文件能力完成后原子替换；目录失败只降级。 | 首装、低存储空间和目录创建失败时仍能出现登录页。 |
| 延后媒体目录产生并发创建 | `warmUp` 单飞并缓存结果。 | 登录后立刻加载封面、进入下载页，确认没有路径为空或重复创建错误。 |
| 方向设置不再阻塞首帧 | 尽早发起平台请求，阅读器既有方向恢复语义不变。 | 竖屏冷启动、横屏系统状态启动、进入/退出阅读器各验证一次。 |
| 原生启动页调整造成平台差异 | Android/iOS 使用同一背景和现有图标比例，不改变宿主业务。 | Android 冷启动/热启动与 iOS 冷启动均检查无白/黑闪。 |

## 7. 不建议的做法

- 不把 SQLite、内置书源导入、下载恢复或 bootstrap 放回 `runApp` 前。
- 不通过无限长启动遮罩掩盖网络超时。
- 不为提升速度把 Token 改存 SQLite、普通偏好或日志。
- 不在 Widget `build()` 中创建依赖、发网络请求或启动后台任务。
- 不把所有初始化简单并发：书源导入和下载恢复仍必须串行，且安全会话刷新必须单飞。
