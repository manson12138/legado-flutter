# 同书名加入书架冲突与覆盖合并设计

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`。本文于 2026-07-30 完成静态分析和实施；没有运行编译、测试、分析、格式化或应用。

## 1. 用户目标

网络书加入书架时，只要当前游客或登录账号的书架中已经存在书名完全相同的书，就必须提示：

- `覆盖`：把新结果视为现有书籍的新来源，合并为一条书架记录；
- `再次添加`：明确保留为另一条书架记录。

作者不再参与冲突判定。这样即使同名书的作者不同，也会先让用户确认，避免仅凭作者字段缺失、别名或解析差异静默生成重复书架项。

## 2. 当前实现事实

`Book` 没有独立数字 ID，当前用户作用域内以 `(userId, bookUrl)` 作为 SQLite 主键。实施前的加入书架链路为：

```text
BookInfoViewModel
  -> AddBookToBookshelfUseCase
  -> ResolveBookShelfStateUseCase
  -> 先按 bookUrl 精确查询
  -> 再按 name + author 精确查询
  -> 已入架 / 同名同作者冲突 / 未入架
```

详情页原本已经有“替换并保留数据 / 仍然新增一本”的冲突对话框，覆盖分支复用 `ChangeBookSourceUseCase`。该 UseCase 会让新书的 `bookUrl`、目录和书源成为当前数据，同时迁移旧书的阅读进度、分组、排序、备注、自定义封面和单书阅读配置。

实施前有两个不符合新目标的点：

1. 冲突查询要求书名和作者都相同；
2. 阅读器的显式加入按钮直接调用 `addAsNew`，绕过了冲突提示。

本地书导入使用内容指纹生成 `local://` 主键，并具有文件复制、重复内容覆盖和失败补偿语义；本次“书源合并”不适用于本地书。

## 3. 已实施行为

### 3.1 匹配顺序

仅对用户主动加入的网络书执行以下顺序：

1. 先按当前用户的 `(userId, bookUrl)` 查询。
2. 如果相同 `bookUrl` 已存在，保持“该来源书籍已在书架中”，不允许再次插入相同主键，也不展示无法完成的“再次添加”选项。
3. 如果 `bookUrl` 不同，再按 `(userId, name)` 精确查询，不再比较作者。
4. 命中同名书时展示两项业务选择：`覆盖`、`再次添加`；返回键或点击对话框外部表示取消，不写数据库。
5. 未命中同名书时正常加入。

书名匹配沿用 SQLite 精确字符串语义，不擅自执行 `trim`、大小写折叠、繁简转换或标点归一化，避免把《剑来》和带隐藏后缀、不同大小写或不同版本名的书误合并。后续如需模糊同名，应单独定义可审计的规范化规则。

### 3.2 覆盖的合并规则

`覆盖`的含义是“一条书架记录切换到新来源，同时保留旧记录中的用户事实”，不是在一条 `Book` 内保存多个活动书源。

| 数据 | 覆盖后的来源 |
|---|---|
| `bookUrl`、`tocUrl`、`origin`、`originName`、目录、规则变量 | 新加入书籍 |
| 普通封面 `coverUrl` | 优先使用新书非空封面；新书封面为空时回退旧书普通封面 |
| 自定义封面 `customCoverUrl` | 优先保留旧书非空自定义封面；旧书没有时使用新书自定义封面 |
| 阅读进度、阅读时间、同步时间 | 迁移旧书进度，并按新目录映射章节 |
| 分组、手动排序、允许更新 | 保留旧书用户设置 |
| 自定义分类、备注、自定义简介 | 保留旧书用户设置 |
| 单书阅读配置与显示配置 | 保留旧书配置 |
| 书名、作者、简介、分类、字数、最新章节等来源事实 | 使用新来源解析结果 |

覆盖提交继续使用已有的整书换源事务：

```text
旧书 (oldBookUrl)
  -> 合并新书字段和旧书用户事实
  -> 事务内复查 oldBookUrl 与 newBookUrl
  -> 删除旧主键及旧目录
  -> 写入新主键及新目录
  -> 迁移正文标注主键
  -> 失效旧 URL 关联的阅读缓存
```

如果新书名与旧书名相同但实际是不同作品，用户应选择“再次添加”。对话框需要同时显示旧作者、新作者、旧来源、新来源和章节数，帮助用户避免误覆盖。

### 3.3 “书源合并”的边界

当前持久化 `Book` 只支持一个活动来源。覆盖后：

- 新来源成为当前活动书源；
- 旧来源不作为第二个活动来源继续保存在 `Book` 中；
- 搜索入口已有的候选来源快照仍按现有机制管理，不把临时候选列表塞进书架实体；
- 若未来要求一本书永久保存多个来源并可直接切换，需要新增用户作用域的“书籍逻辑身份—来源列表”关系表、来源唯一约束和迁移策略，属于另一项 Schema 设计，不在本次范围。

### 3.4 再次添加

用户选择“再次添加”时：

- 仍要求新书 `bookUrl` 与现有记录不同；
- 直接保存新书及其目录，不迁移旧书数据；
- 两条书架记录可以书名相同，分别拥有独立进度、封面、分组和当前来源；
- 以后再次添加同名书时仍提示，由用户继续决定。

## 4. 实施范围

| 层 | 文件 | 拟修改职责 |
|---|---|---|
| Domain | `domain/usecase/resolve_book_shelf_state_use_case.dart` | 精确 URL 未命中后改为只按书名解析冲突 |
| Domain | `domain/usecase/add_book_to_bookshelf_use_case.dart` | 保持用户主动加入与后台保存入口分离；覆盖/新增仍进行提交前精确主键复查 |
| Domain | `domain/usecase/change_book_source_use_case.dart` | 补充普通封面的非空回退合并规则，继续迁移全部用户事实 |

| Data | `data/dao/book_dao.dart`、`data/repository/book_repository.dart` | 使用 `userId = ? AND name = ?` 查询同名书；保持 `durChapterTime DESC, bookUrl ASC` 稳定选择 |
| 详情 UI | `ui/book_info/book_info_contract.dart`、`book_info_view_model.dart`、`book_info_route.dart` | 更新冲突状态命名、提示文案、作者/来源展示和两个业务选项 |
| 阅读器 UI | `ui/reader/reader_contract.dart`、`reader_view_model.dart`、`book_reader_route.dart` 或现有对话框宿主 | 显式加入书架改走统一冲突解析，并支持覆盖/再次添加 |
| 组合根 | `app/app_dependencies.dart` | 只在构造依赖签名变化时同步接线 |
| 文档 | 本文、`AI_PROJECT_INDEX.md` | 记录新判重与合并语义 |

书架刷新、启动后台目录更新和本地书重复导入继续调用 `save`，它们是在更新已确认身份的现有记录，不应弹出面向用户的同名冲突框。

## 5. 数据库与存储结论

- 继续使用 SQLite，因为书架、目录、进度和换源属于关系数据与事务状态。
- `books` 主键仍是 `(userId, bookUrl)`；“同名冲突”是加入流程的业务保护，不把书名改成数据库唯一键，因为用户明确允许“再次添加”。
- 现有索引 `(userId, name, author)` 的前缀已经覆盖 `(userId, name)` 查询，本次不需要新增索引、修改表结构或升级 `LegadoDatabase.schemaVersion`，也不需要提高 `pubspec.yaml` build number。
- 已经存在的同名重复书不会在升级时自动删除或批量合并，避免未经用户确认丢失进度、下载或备注。新加入动作只处理本次命中的一条稳定现有记录。

## 5.1 实施快照

- `BookShelfState` 已从“同名同作者”改为“同书名”冲突，精确 `bookUrl` 查询仍优先。
- `BookshelfGateway`、`BookRepository` 和 `BookDao` 已改为按当前 `userId + name` 查询，作者不再参与判重。
- 详情页冲突框只提供“覆盖”和“再次添加”两个业务选项；返回键或点击外部取消。
- 阅读器显式加入按钮已从直接 `addAsNew` 改为统一调用 `execute`，并补齐同样的冲突状态、对话框和两个确认动作。
- 覆盖继续复用 `ChangeBookSourceUseCase`；新普通封面为空时回退旧普通封面，旧自定义封面非空时优先保留。
- 同书名覆盖允许把现有本地书架记录明确切换成当前网络来源，但普通整书换源入口仍拒绝本地旧书；本地文件导入和内容指纹更新逻辑没有改变。
- 没有修改数据库表、主键或索引，没有升级 Schema 和构建号。

## 6. 并发、性能与内存

- 同名查询必须限定当前 `userId`，最多读取一条记录，不把全书架加载到 Dart 后再过滤。
- 查询使用 `durChapterTime DESC, bookUrl ASC`，存在历史重复项时稳定选择最近阅读的一条作为本次覆盖目标。
- 对话框展示期间不持有数据库事务；覆盖提交时在短事务内重新检查旧主键和目标新主键，避免并发加入覆盖错误记录。
- UI 状态只保存冲突所需的现有书、新书和新目录，不复制正文，不增加长期大对象。
- 覆盖成功后沿用现有缓存失效、路由主键替换和流通知，避免旧 `bookUrl` 页面或异步任务晚到回写。

## 7. 明确不包含

- 不把书名改成数据库唯一键。
- 不自动合并或删除历史上已经存在的全部同名书。
- 不在一条书架记录中永久保存多个活动书源或多个封面列表。
- 不修改本地书内容指纹导入与重复内容更新逻辑。
- 不新增 MMKV 数据、平台通道、权限或原生 Android/iOS 业务代码。
- 不处理批量导入、远端书架同步或服务端逻辑。

## 8. 用户验收建议

1. 书名和作者都相同、`bookUrl` 不同：加入时出现覆盖/再次添加提示。
2. 书名相同、作者不同、`bookUrl` 不同：同样出现提示，且对话框能看清两位作者和两个来源。
3. 选择再次添加：书架保留两本同名书，进度和来源相互独立。
4. 选择覆盖：书架只替换命中的旧记录；当前来源和目录切到新来源，旧阅读进度、分组、备注和自定义封面保留。
5. 新来源没有普通封面：继续显示旧普通封面；新来源有封面且旧书没有自定义封面：显示新封面。
6. 相同 `bookUrl` 再次加入：提示已经在书架中，不产生重复记录。
7. 从书籍详情和阅读器显式加入入口分别重复以上场景，行为一致。
8. 游客、账号 A、账号 B 分别验证：同名冲突只在当前作用域内出现，不跨用户串书。
9. 书架刷新、启动后台目录更新和本地书重复导入不弹出同名冲突框。
10. 覆盖后打开正文、返回书架、更新目录、换源、删除和离线下载，确认没有旧 URL 残留或错误路由。
