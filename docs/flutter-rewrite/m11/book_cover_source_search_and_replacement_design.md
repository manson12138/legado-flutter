# 书源封面搜索与替换设计

状态：`IMPLEMENTED / 代码已写入，等待用户运行验收`

## 1. 目标

在以下两个入口提供统一的“更换封面”能力：

- 书架长按选中一本书后的操作栏；
- 书籍详情页的显式操作入口，并接通现有“更换封面”菜单和封面长按入口。

点击后先展示当前封面和已有候选；没有可用候选时，自动从当前可见且已启用的书源搜索封面。用户选择后只更新书架记录的 `customCoverUrl`，不修改书籍来源、目录、阅读进度、分组或标签。

## 2. Android 参考结论

Android 参考实现位于：

- `app/src/main/java/io/legado/app/ui/book/changecover/ChangeCoverViewModel.kt`
- `app/src/main/java/io/legado/app/ui/book/changecover/ChangeCoverDialog.kt`
- `app/src/main/java/io/legado/app/ui/book/changecover/CoverAdapter.kt`
- `app/src/main/java/io/legado/app/ui/book/info/edit/BookInfoEditScreen.kt`

其主要行为是：

1. 先读取已启用书源对应的封面缓存；
2. 缓存中没有候选时自动搜索全部已启用书源；
3. Android 当前只接受“书名和作者都精确相同且封面非空”的搜索结果；
4. 弹出封面网格，允许停止或重新搜索；
5. 选择默认封面时清空 `customCoverUrl`，选择网络封面时保存封面 URL。

Flutter 实现复用这套交互和持久化语义，但按照本任务要求扩展为三个有严格优先级的匹配层级。

Android 的书籍信息编辑页还通过 `SelectImageContract` 选择本地图片，并由
`BookInfoEditViewModel.coverChangeTo` 复制到应用私有 `covers` 目录。Flutter 共用封面面板现已补齐
该入口：Android 与 iOS 都使用系统图片选择器，选择结果立即复制到应用支持目录，不长期依赖 SAF 或
Document Picker 的外部路径权限。

## 3. 匹配与候选选择规则

### 3.1 前置过滤

任何层级的候选都必须满足：

- `coverUrl.trim()` 非空；
- 结果来自当前可见且已启用的书源；
- 结果仍属于本次页面实例和本次搜索代次，已取消或过期任务的回调不得进入状态。

当前已保存的自定义封面不受书源启用状态影响，始终允许继续显示和使用。

### 3.2 三级优先顺序

候选按照以下顺序分层：

1. **一级：书名精确匹配，并且作者精确匹配**
2. **二级：书名精确匹配**
3. **三级：书名模糊匹配**

只展示当前存在结果的最高层级，不混合展示低层级结果。例如：

- 已有一级结果时，只展示一级结果；
- 没有一级但有二级结果时，只展示二级结果；
- 一级、二级都没有时，才展示三级结果。

搜索结果由多个书源并发返回，候选层级必须支持动态升级：

- 先收到三级结果时可以先展示三级结果；
- 后续收到二级结果时立即用二级候选集替换三级候选集；
- 后续再收到一级结果时立即用一级候选集替换二级候选集；
- 已进入更高层级后，后续低层级结果只在当前搜索代次内暂存，不再展示。

即使已经发现一级结果，也继续完成其他书源的搜索，以便收集多个精确匹配的封面供用户选择。

### 3.3 标准化规则

精确书名比较：

- 去除首尾空白；
- 连续空白折叠为一个空格；
- 英文字母忽略大小写；
- 不移除书名标点，不把不同标点版本当成精确匹配。

精确作者比较：

- 使用与书源换源流程一致的作者标准化；
- 去除首尾空白、连续空白和英文字母大小写差异；
- 去除常见的 `作者:` / `作者：` 前缀和末尾 `著`；
- 目标书籍作者为空时，不进入一级，只能从二级开始匹配，避免两个空作者被误判为高置信结果。

书名模糊比较：

- 在精确书名标准化基础上，再移除书名号、括号、常见连接符和空白；
- 候选书名包含目标书名，或目标书名包含候选书名，即视为模糊匹配；
- 两边较短的有效名称至少包含 2 个字符，避免单字书名造成大量误匹配。

### 3.4 去重与排序

- 用标准化后的封面 URL 去重，避免不同书源返回同一图片时重复占位；
- 同一层级内按书源 `customOrder` 排序；
- 同一书源内保持返回顺序；
- 当前封面和“恢复默认封面”固定置于候选网格最前，不参与三级匹配排序。

## 4. 数据流与职责

### 4.1 复用现有搜索调度

封面搜索复用 `BookSearchCoordinator`：

- 使用目标书名作为搜索关键字；
- 搜索范围是当前可见且已启用的全部书源；
- 复用固定并发数、单书源超时、取消和代次隔离；
- 每批搜索结果到达后立即过滤、分层和更新界面，不为每个书源创建无界任务。

新增页面级 `BookCoverSearchCoordinator`，只负责：

- 合并详情页已有结果、SQLite 缓存和实时搜索结果；
- 执行封面非空过滤、三级匹配、动态层级升级和 URL 去重；
- 暴露进度、失败数、当前展示层级、停止和重试状态；
- 页面销毁时取消当前 `BookSearchRun`，释放订阅和回调。

### 4.2 候选缓存

复用现有 SQLite `searchBooks` 表作为派生缓存，不新增表、不改数据库结构：

- 扩展 `SearchBookDao`，按启用书源、非空封面和书名相关条件读取最多 200 条候选；
- SQL 先约束精确或双向包含关系，Dart 层再执行统一的标准化和三级排名；
- 实时搜索接受的候选按现有 `SearchBook` 结构回写缓存；
- 缓存只用于减少重复搜索，不是用户书架业务数据。

不复用 `book_source_candidates`：该数据用于书籍详情的换源候选快照，混入封面搜索结果会改变详情页的书源数量和排序语义。

### 4.3 保存封面

为书架数据增加字段级更新链路：

`UpdateBookCustomCoverUseCase`
→ `BookshelfGateway.updateCustomCover`
→ `BookRepository.updateCustomCover`
→ `BookDao.updateCustomCover`

更新条件使用当前用户与书籍主键 `bookUrl`，只更新 `customCoverUrl`：

- 选择远程候选：保存候选 `coverUrl`；
- 选择“恢复默认封面”：保存 `null`；
- 不使用整行 `upsert`，避免页面持有的旧书籍对象覆盖阅读进度等新状态；
- 更新成功后通知书架监听流，书架封面自动刷新。

`books.customCoverUrl` 已存在，因此不提升 `LegadoDatabase.schemaVersion`，也不修改 `pubspec.yaml` 构建号。

## 5. 页面与交互

### 5.1 通用封面选择底部面板

新增可被书架和详情页共同调用的底部面板：

- 顶部显示标题、搜索状态、进度和停止/刷新按钮；
- 主体使用懒加载自适应网格展示封面，窄屏 2 列、常规手机 3 列、宽屏 4 列；
- 每项显示封面及来源名称，使用稳定 key；
- 搜索期间保留当前候选，不因进度更新重建图片对象；
- 搜索部分失败时保留已成功结果，并显示失败数量；
- 没有缓存候选且存在可搜索书源时自动开始搜索；
- 用户点击刷新时取消旧代次并重新搜索；
- 用户关闭面板时立即取消搜索。

书源状态提示：

- 没有任何可见书源：`当前没有书源，无法搜索封面`；
- 有书源但没有启用项：`当前没有开启的书源，无法搜索封面`；
- 搜索完成仍没有结果：`没有找到匹配且封面非空的结果`。

“恢复默认封面”始终可用，因此无书源时用户仍可清除自定义封面。

头部同时提供“选择本地图片”入口。选中的图片先按书籍主键与内容摘要复制到
`Application Support/custom_book_covers`。数据库不保存可能随 iOS 容器变化的绝对路径，只保存
`legado-cover://local/<文件名>` 稳定标识，显示时再同步解析为本次运行的真实沙盒路径；旧版本已经保存的
`.../custom_book_covers/<文件名>` 绝对路径会自动按文件名兼容。复制成功后仍复用
`UpdateBookCustomCoverUseCase` 字段级写入；
保存失败会删除未生效副本，后续换成网络封面、另一张本地图片或恢复默认时会删除该书旧的受管副本。
网络地址、应用目录之外的历史路径和其他书籍文件不会被清理。

字段更新在同一 SQLite 事务内同时写入 `books` 和已存在的 `reading_history_books` 快照；没有历史记录时
不会为换封面凭空创建历史。公共 `BookCover` 同步复用本进程已成功显示的稳定封面标识与 Flutter 图片
缓存，书架/历史页面重建时不再先走异步地址兜底而闪出无封面占位。

### 5.2 书架入口

保持现有“长按进入选择模式”的交互，在选择模式操作栏增加封面替换按钮：

- 只选择一本书时启用；
- 选择零本或多本时禁用；
- 点击后打开通用封面选择面板；
- 保存成功后退出选择模式并提示“封面已更新”；
- 书架依靠数据库监听流刷新，不额外复制书籍列表。

### 5.3 书籍详情入口

详情页增加一个可见的“更换封面”操作，并接通已有入口：

- 页面操作区的“更换封面”按钮；
- 右上角菜单中的“更换封面”；
- 封面长按。

三个入口调用同一 ViewModel intent 和同一通用底部面板。详情页已有的搜索分组可作为首批内存候选，再与 SQLite 缓存合并。

只有已加入书架的书籍才能持久化自定义封面。详情页书籍不在书架时，点击后提示“请先加入书架再更换封面”，不隐式加入书架，也不保存仅在当前页面生效的临时状态。

保存成功后用返回的新 `Book` 更新详情页状态，使详情封面立即刷新；同时数据库通知书架流。

## 7. 性能与生命周期约束

- 搜索固定使用现有最多 4 路并发，不随书源数量创建等量并发任务；
- 缓存查询最多返回 200 条，避免无界读取 `searchBooks`；
- 候选只保存必要的书名、作者、封面 URL、来源和书籍 URL；
- 图片继续使用现有 `BookCover` 与 Flutter 图片缓存，不新增原图常驻内存缓存；
- 应用启动后立即预热本地封面目录，后续页面切换同步解析稳定标识，不重复等待 `path_provider`；
- 网格采用懒构建，不一次性实例化全部图片；
- ViewModel 不保存 `BuildContext`；
- 面板关闭、目标书变化或重试时都取消旧搜索，旧代次结果不得回写新状态；
- 字段级 SQL 更新避免整书覆盖，并减少无关数据库写入和列表抖动。

## 8. 验收要点

1. 书架长按只选一本时可以打开“更换封面”，多选时按钮不可用。
2. 详情页按钮、菜单和封面长按均打开同一个面板。
3. 所有空封面结果都不会出现。
4. 一级结果存在时只显示书名和作者都精确匹配的结果。
5. 没有一级结果但有二级结果时，只显示书名精确匹配的结果。
6. 一级、二级都没有时，才显示书名模糊匹配的结果。
7. 并发搜索先返回模糊结果、后返回精确结果时，界面会自动升级且不混杂低层级结果。
8. 没有缓存候选且有启用书源时自动搜索；没有书源或没有启用书源时给出对应提示。
9. 选择候选只修改 `customCoverUrl`；选择恢复默认只清空 `customCoverUrl`。
10. 搜索中关闭面板后不再更新已销毁页面，重新搜索不会接收上一代结果。
11. 不新增数据库字段，不提升数据库版本和应用构建号。
12. 无书源或搜索无结果时仍可选择本地图片；保存后重启应用封面继续可用，换成其他封面时不会误删相册原图。
13. 本地封面在书架和已有阅读历史中同步更新；两个页面来回切换时不再重复显示“无封面 → 本地封面”。

## 9. 实施记录

代码已按本设计写入：

- `lib/src/model/web_book/book_cover_search_coordinator.dart` 负责三级匹配、动态升级、缓存合并和有限并发搜索；
- `lib/src/ui/change_book_cover/` 提供共用 MVI 状态、ViewModel 和自适应底部面板；
- `lib/src/platform/local_book_cover_service.dart` 负责双端系统图片选择、应用私有副本和受控清理；
- `BookDao`、`BookshelfGateway`、`BookRepository` 与 `UpdateBookCustomCoverUseCase` 使用字段级 SQL 更新 `customCoverUrl`；
- `BookRepository` 在同一事务内同步书架和已有阅读历史快照的 `customCoverUrl`；
- `SearchBookDao` 与 `BookCoverCandidateRepository` 复用 `searchBooks`，查询最多 200 条非空封面缓存；
- 书架长按单选操作栏和书籍详情操作卡、菜单、封面长按均已接入共用面板；
- 面板关闭、停止和重新搜索都会取消旧 `BookSearchRun`，并以搜索代次拒绝迟到事件；
- 面板头部可直接选择本地图片，即使没有书源或搜索无结果也能完成换封面。
- 本地封面改存稳定 `legado-cover` 标识并兼容旧绝对路径，公共封面组件增加同步内存快路径，修复重启丢图和页面切换闪占位。

依照项目约束，本轮没有运行 Flutter、Dart、构建、测试、分析、格式化或应用启动命令，功能等待用户验收。
