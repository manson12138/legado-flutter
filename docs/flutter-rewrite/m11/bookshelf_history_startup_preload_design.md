# 书架与阅读历史启动预加载设计

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`。本文基于 2026-07-25 的静态梳理与实施；未运行编译、测试、分析、格式化或应用。

## 1. 目标

在已恢复本地会话或登录成功、即将进入主界面的启动遮罩期间，开始读取本地书架、书架分组和阅读历史首个快照，使进入主界面时优先使用已完成的内存快照，减少书架与历史页的圆形 `loading`。未登录时只显示登录界面，绝不发起该预加载或打开书架/历史 SQLite 数据。

本次预加载仅访问本地 SQLite，不请求书源、不刷新目录、不导入书源、不恢复下载，也不改变书架与历史的持久化内容。

## 2. 当前原因

- `BookshelfViewModel` 创建后才分别订阅书架和分组流；两条流各自首次异步查询 SQLite 前，`loading` 保持为 `true`。
- `ReadingHistoryViewModel` 创建后才订阅历史流；首次异步查询返回前也显示圆形 `loading`。
- 书架的线性进度条只表示用户显式发起的“刷新目录”，不属于本方案的预加载范围。

## 3. 实施边界与链路

```text
已恢复本地会话或登录成功
  -> 主界面启动遮罩可见，完整依赖已创建
  -> 单飞启动“书架 + 分组 + 阅读历史”本地快照预加载
  -> SQLite 连接和首批查询完成后缓存不可变快照
  -> 书架/历史 ViewModel 创建时先消费对应快照
  -> 继续订阅现有数据库流，后续写入仍实时更新 UI
```

预加载任务不应被 `await` 到启动遮罩、认证恢复或登录输入就绪链路中：慢磁盘只能让页面保留现有短暂加载态，不能让启动页因本地查询而无限停留。数据库连接沿用 `LegadoDatabase` 已有的单一 `Future<Database>`，避免重复打开连接；任务本身需要单飞、缓存成功快照，并在失败后把异常交给页面的现有流读取路径兜底。

## 4. 拟修改范围

- 新增应用级本地快照预加载服务，集中并行读取书架书籍、书架分组和阅读历史书籍，并保存不可变结果。
- 在 `LegadoApp` 确认会话存在的主界面启动遮罩期间发起该服务；未登录的认证启动路径不触发它。不与登录后的内置书源导入/下载恢复串行任务混用。
- 在 `AppDependencies` 装配并向书架路由传递预加载服务。
- `BookshelfViewModel` 与 `ReadingHistoryViewModel` 先应用对应预加载快照，再保持现有 `watchBookshelf` / `watchGroups` / `watchHistory` 订阅作为实时真相来源。
- 文档索引已更新；预加载本身不改远端 API、书架刷新协调器或阅读历史写入逻辑。后续用户隔离专项已把数据库升级到 v9，预加载现在必须携带当前用户 ID。

## 5. 一致性、性能与资源约束

- 快照只用于首屏，数据库流始终为后续更新的唯一来源；预加载与页面订阅之间发生的写入必须由流事件覆盖，不能丢失。
- 缓存列表使用不可变集合，避免页面修改共享内存；页面销毁仍取消现有订阅，不保留 `BuildContext`、页面回调或 `StreamSubscription`。
- 书架、分组、历史三项读取可并行，但不与“刷新目录”建立关联，也不显示目录刷新进度。
- 如果预加载未完成就进入书架页，保留当前圆形加载；完成后应直接展示内容。这样保证首帧和认证输入不受慢 SQLite 阻塞。
- 单飞任务同时捕获用户 ID 和作用域代次；退出或切换账号时立即清空缓存句柄，旧查询即使完成也不能发布到新账号页面。

## 6. 用户验收

1. 已有书架和历史时冷启动，进入主界面后确认书架和历史通常直接显示内容；不应出现目录刷新线性进度。
2. 首装/空数据时确认显示空态，不会永久转圈。
3. 冷启动后立即新增、删除书架书籍或完成一次阅读，确认两个页面仍随数据库写入实时更新。
4. 点击书架刷新，确认只有此时才出现线性刷新进度并发起书源网络请求。
5. 未登录冷启动时确认只出现登录界面，且不读取书架/历史；在慢设备或大量书籍场景确认登录输入、启动遮罩退出与页面进入没有被 SQLite 预加载阻塞。
