# 阅读器无转圈进入、显示配置预热与首次阅读先导页设计

状态：`SUPERSEDED`。当前实施入口已合并到
[`mmkv_and_reader_entry_loading_optimization_plan.md`](./mmkv_and_reader_entry_loading_optimization_plan.md)。

> 本文只记录设计与实施边界。尚未修改业务代码，也未运行 Flutter、Dart、构建、测试、
> 静态分析、格式化或应用启动。

## 1. 目标与非目标

本专项唯一目标是消除小说文本阅读器“每次进入都先显示通用圆形 loading”的体验，并在不牺牲
进度正确性、正文缓存一致性和内存边界的前提下，让本地数据读取尽量被 250 毫秒路由转场覆盖。

目标体验：

- 重复打开已预热章节时，转场结束直接显示上次阅读位置，不出现通用 loading。
- 第一次打开一本书时，先显示有实际信息的阅读先导页；正文未就绪时禁止翻页并给出节流提示，
  正文就绪后允许滑动或点击“开始阅读”进入正文。
- 只有正文获取、处理和首个可读页面属于进入阅读的关键链；书签、标注、相邻章预加载、埋点、
  电量等继续在页面出现后异步完成。
- 慢网络、正文规则失败和本地缓存损坏时保留书籍信息与明确的错误/重试入口，不退化为空白页或
  无限转圈。

本专项不包含：

- 修改 Android 参考工程；
- 把全部书籍正文在 App 启动时读取或请求网络；
- 持久化 Flutter Widget、分页控制器或完整页面位图；
- 把正文、阅读进度或关系数据迁移到 MMKV；
- 修改数据库 Schema、书源格式或阅读进度含义；
- 重做正文分页、仿真翻页和原生文字选区。

## 2. 当前事实与根因

### 2.1 显示配置不在 MMKV

当前工程没有接入 MMKV。`ReaderDisplayConfig` 由
`ReaderRepository.getDisplayConfig/saveDisplayConfig` 以 JSON 保存到 SQLite `caches` 表：

- 当前全局键：`reader:config:global`；
- `deadline=0`，永久有效；
- 旧版 `reader:config:<bookUrl digest>` 只在全局键不存在时兼容读取；
- 配置已经是设备级全局偏好，不是每本书独立读取不同配置。

因此显示配置本身通常只是一条 SQLite 查询和一次小 JSON 解码。问题不是它“很慢”，而是当前每次
创建阅读器都把它放在串行初始化链里重新读取，并且读取完成前页面没有可同步使用的配置快照。用户已
提出为项目增加 MMKV；依赖版本、ABI 取舍、存储边界和迁移方案见
[`mmkv_non_relational_preferences_design.md`](./mmkv_non_relational_preferences_design.md)。

### 2.2 当前进入链存在两层 loading 和重复查询

```text
点击书籍
  -> BookReaderRoute
       -> 再查一次书籍，用于区分 PDF / 文本
       -> Future 未完成时显示圆形 loading
  -> ReaderRoute 新建 ReaderViewModel 和 ReadBookCoordinator
       -> ReaderUiState 初始 content=null
       -> ReaderScreen 再显示圆形 loading
       -> 依次读取书籍、目录、显示配置、锚点、旧进度
       -> 把 loadState 设为 loading 并加载正文
       -> 正文完成后才显示阅读内容
```

书架和历史 Effect 已经持有完整 `Book`，但当前导航只传 `bookUrl`；统一阅读入口随后重新查询同一本书，
文本阅读器 ViewModel 又再次查询。详情入口已经传入 `Book` 和完整目录快照，书架与历史没有复用同类
能力。

### 2.3 命中持久缓存仍不能同步显示正文

持久缓存只保存书源解析后的原始正文。每次重新进入仍需：

1. 从 SQLite 读取原始正文；
2. 读取当前生效的正文替换规则；
3. 执行 HTML 清理、替换、简繁转换、重新分段和正文分块；
4. 发布新的 `ReaderChapterContent`；
5. 由分页层恢复首个可读页面。

处理后的正文 LRU 位于页面生命周期独占的 `ReadBookCoordinator` 内。退出页面时协调器会清空最多三章的
内存缓存，因此下次进入无法复用刚才已经处理完成的正文。

## 3. 推荐产品行为

### 3.1 首次打开：书籍先导页作为第 0 页

“首次打开”建议使用现有事实综合判断，不新增数据库字段：

```text
Book.durChapterTime == 0
并且没有有效阅读历史或稳定正文锚点
```

出现数据不一致时，只要存在历史或锚点，就按“曾经阅读”处理，避免升级或异常退出后反复显示先导页。

先导页内容：

- 上半部分：封面、书名、作者；
- 中部：准备打开的章节标题、当前章节序号、已知总章节数、书源名称；
- 下半部分：自定义简介优先，其次书源简介，均为空时显示“暂无简介”；
- 底部：正文未就绪时显示轻量状态文案；就绪后显示“开始阅读”操作和可滑动提示。

先导页不等待封面网络请求。它直接使用已有 `Book` 快照和封面组件；封面缓存或网络图片独立加载，
失败时保留现有占位，不得阻塞正文。

交互规则：

- 正文未就绪时，正文方向的滑动不移动页面；
- 达到手势阈值后提示“章节正在准备，完成后即可阅读”，同一提示需要节流，避免连续手势重复弹出；
- 系统返回、配置允许的边缘返回仍可退出，不能把用户困在先导页；
- 正文就绪后允许按当前阅读模式向正文方向滑动，也提供“开始阅读”按钮满足无障碍和不熟悉手势的用户；
- 第一次真正显示正文页时再形成“阅读已打开”的产品语义，避免用户只看先导页就被统计为已经阅读。

### 3.2 重复打开：直接恢复，冷缓存时使用简化恢复页

重复打开分为三种情况：

| 情况 | 目标表现 |
|---|---|
| 处理后正文内存命中 | 250ms 转场结束直接显示正文与上次位置，不出现 loading |
| 仅原始正文持久缓存命中 | 转场期间完成 SQLite 读取和正文处理；若按时完成则直接显示正文 |
| 无可用正文缓存或处理超出转场 | 显示简化恢复页，包含封面、书名和目标章节，不显示通用转圈；就绪后自动淡入正文 |

简化恢复页不是“首次先导页”，不要求用户再点击开始阅读。正文首个可读页面准备完成后直接以短淡入替换，
同时恢复字符锚点。

### 3.3 错误状态

- 首次先导页加载失败：保留书籍信息，在底部显示错误摘要与“重试”。
- 重复恢复页加载失败：保留上次章节信息并显示“重试/返回”。
- 强制刷新失败不能回退到旧缓存伪装成功；用户主动刷新时继续沿用现有错误语义。
- 取消、路由释放或账号切换产生的旧任务不得覆盖当前页面。

## 4. 显示配置 MMKV 内存快照

### 4.1 新增应用级内存配置持有者

建议在 MMKV 初始化完成后增加轻量的 `ReaderDisplayConfigStore`，由 `AppDependencies` 创建并注入：

- 构造时同步提供跨平台默认配置，因此任何阅读页面首帧都有可用颜色、亮度、方向和阅读模式；
- App 首帧后单飞初始化 MMKV，并把 SQLite `reader:config:global` 兼容迁移到 MMKV；
- 成功后在内存保存唯一当前配置；
- 页面读取优先使用同步内存值，不再每次直接查询 SQLite；
- 设置修改时先更新内存，再同步写入 MMKV；写入失败仍由现有错误反馈处理；
- 配置是设备级偏好，账号切换不清除。

MMKV 只承担小型非关系偏好；正文、阅读进度、书架和下载队列继续使用 SQLite。业务通过项目内偏好接口
访问，不直接依赖 MMKV 类型。

### 4.2 启动时机

配置预热必须遵守现有启动性能边界：

- 不放到 `runApp()` 之前；
- 不阻塞原生启动页、Flutter 首帧、认证输入或主界面展示；
- 在 Flutter 首帧后等待官方 `MMKV.initialize()`，再创建正式 `AppDependencies`；
- MMKV 初始化失败时降级为进程内默认值与一次 SQLite 兼容读取，不能永久阻断 App；
- 正式配置到达后，在正文布局开始前应用，避免先按默认字号处理、随后又按真实字号重复分页。

## 5. 进入阅读器的数据快照

### 5.1 路由参数复用已有书籍事实

`ReaderRouteArguments` 应允许所有入口传入当前 `Book` 快照，而不是只把 `initialBook` 理解为未入架详情书：

- 书架入口直接传 Effect 已持有的 `Book`；
- 历史入口直接传历史列表已持有的 `Book`；
- 详情入口继续传 `Book + chapters`；
- 同时携带明确的 `isInBookshelf` 或入口来源事实，避免 ViewModel 为判断悬浮按钮再次查询书架；
- `BookReaderRoute` 使用同一快照完成 PDF/文本分流，不再先查一次、文本 ViewModel 再查一次。

如果入口没有快照或快照主键不匹配，才回退现有 Repository 查询。数据库仍是最终事实来源，路由快照只用于
消除进入首帧的重复等待；页面建立后与进度保存相关的写入继续走现有 UseCase/Repository。

### 5.2 目录与目标章节

- 详情入口已有完整目录，直接复用。
- 书架/历史入口不应在 App 启动时预读所有书的完整目录，这会随书架规模放大 SQLite I/O 和内存占用。
- 点击书籍后立即读取目标书目录，并与锚点、旧进度、配置任务并发。
- 若启动快照以后增加“最近阅读书目录”，最多只保留最近一本，不做无界全书架预热。
- 目录准备前先导/恢复壳可使用 `Book.durChapterTitle`、`durChapterIndex` 和
  `totalChapterNum` 展示已有信息；目录到达后再补充精确章节标题。

## 6. 共享的处理后正文缓存

### 6.1 缓存职责

页面生命周期内的网络取消令牌、预加载 worker 和 ViewModel 状态仍由独占
`ReadBookCoordinator` 管理；只把纯数据 `ReaderChapterContent` 缓存提取为应用级有界 LRU。

建议缓存键至少包含：

- 当前用户 ID；
- `bookUrl + chapterUrl`；
- 是否启用替换规则；
- 简繁转换模式；
- 重新分段开关；
- 可使正文结果失效的替换规则版本或显式失效代次。

缓存对象不得持有 `BuildContext`、Widget、Controller、FocusNode、StreamSubscription、Timer、
平台对象或网络取消令牌。

### 6.2 容量与失效

- 默认最多保留三章处理后正文，与现有页面内 LRU 上限一致；
- 同时设置估算字节预算，防止三个超长章节占用不可控内存；
- 系统内存压力时立即清空；
- 账号切换时清空，避免不同用户作用域复用内存正文；
- 强制刷新、单章换源、删除离线正文、整书换源和正文替换规则变化时按书/章精确失效；
- 字号、行高、边距等纯分页参数不必使正文处理缓存失效，但必须使完整分页 LRU 失效；
- 不把处理后正文永久写入 SQLite，避免规则和处理版本升级后读取陈旧结果。

### 6.3 启动期低优先级预热

App 启动后可以对“最近阅读的一本书当前章”做受控预热，但必须满足：

- 只读取已经存在且未过期的原始正文缓存；
- 绝不因启动预热发起书源网络请求；
- 等主界面首帧和显示配置预热完成后再低优先级执行；
- 用户点击阅读、下载或其他前台正文任务时立即让路或取消；
- 只预热一本书当前章，成功结果进入同一个三章 LRU；
- 内存压力、账号切换和前后台策略变化时可直接丢弃，不影响持久数据。

这项优化能覆盖最常见的“启动 App 后继续读上次一本书”，但应作为第二阶段；第一阶段先消除重复查询和
通用 loading。

## 7. 250 毫秒阅读器转场

阅读器路由建议使用专用 `PageRouteBuilder`，而不是继续依赖默认 `MaterialPageRoute`：

- `transitionDuration = 250ms`；
- 入场使用轻微位移加淡入，曲线使用 `easeOutCubic` 或等价平滑曲线；
- 退出使用更短或同长的反向动画，不能影响“保存进度后再关闭”的现有单飞链；
- 系统开启“减少动态效果”时禁用位移并缩短/取消动画；
- 不在动画期间做主 isolate 大段正文处理；现有正文处理继续使用后台 isolate；
- 不使用全屏位图快照，避免额外显存和超长页面截图成本。

250 毫秒动画不会让数据库或网络本身更快，只能覆盖很短的本地读取。要达到“看不到 loading”，必须与
书籍快照复用、显示配置内存快照、并行初始化和处理后正文 LRU 同时实施。

首批不强制封面 Hero。书架/历史双页可能同时保留同一本书的封面 Widget，直接使用普通 bookUrl Hero Tag
容易发生重复 Tag；可先使用稳定的淡入/位移转场，后续如需要共享元素动画，再按入口页面和书籍摘要构造
唯一 Tag。

## 8. 关键链与延后链

### 8.1 正文首显前必须完成

- 可验证的 `Book` 快照；
- 全局 `ReaderDisplayConfig`，至少是同一个单飞任务的最终值；
- 目标章节及其稳定 URL；
- 当前章处理后正文；
- 用于恢复位置的稳定锚点或旧进度；
- 当前阅读模式首个可读页面。

### 8.2 页面出现后异步完成

- 书签列表；
- 当前章节高亮/下划线订阅；
- 完整替换规则列表（设置或统计面板使用）；
- 上一章/下一章预加载；
- 电量和时间刷新；
- 阅读历史持久化与匿名埋点；
- 非当前章节的目录刷新、封面补全和下载状态。

这些旁路任务失败不能把已经可读的正文重新改成 loading。

## 9. 推荐实施阶段

### P0：直接消除每次进入的通用 loading

1. 接入 MMKV 和应用级显示配置 Store，首帧后单飞初始化、迁移并同步复用。
2. 书架、历史、详情都向阅读路由传递已有 `Book` 快照；统一入口只在缺少快照时查库。
3. 将目录、锚点、旧进度和必要本地事实并行读取，保留用户作用域和加载世代校验。
4. 增加 250 毫秒阅读器专用转场。
5. 用首次先导页和重复恢复页替换两个圆形 loading。
6. 正文未就绪时禁用正文方向翻页，并提供节流提示、返回和错误重试。

P0 不需要数据库 Schema 或 `pubspec.yaml` 版本变更。

### P1：重复进入和继续阅读预热

1. 抽取应用级三章处理后正文 LRU。
2. 接入内存压力、账号切换、换源、刷新、下载删除和替换规则变化失效。
3. 启动后仅从持久原始缓存低优先级预热最近阅读一本书的当前章。

### P2：基于用户真机结果继续压缩

- 如果 250 毫秒后仍经常停留在恢复页，再根据现有耗时日志区分 SQLite、正文处理和分页首屏耗时；
- 只优化真实最长阶段，不增加无界缓存或启动网络预取；
- 如首个可读页面仍慢，再单独评估分页首屏增量预算，不在本专项顺带重写分页器。

## 11. 性能与内存验收

由用户执行以下人工验收：

1. 冷启动后立即打开书架第一本书，确认没有通用圆形 loading；配置预热未完成也不出现白/黑闪。
2. 第一次打开从未阅读的书，确认显示封面、书名、作者、章节信息和简介。
3. 正文未就绪时连续滑动，确认页面不移动、提示被节流、返回仍可用。
4. 正文就绪后通过滑动和“开始阅读”分别进入正文，确认字符锚点从正确章节开始。
5. 退出后立即再次进入同一书，确认 250 毫秒转场结束直接看到上次位置。
6. 杀进程后重新打开最近阅读书，确认只使用已有正文缓存预热；断网时不得偷偷发起启动网络请求。
7. 打开未缓存网络章节，确认显示有内容的恢复页，网络成功后自动进入正文，失败后显示重试。
8. 快速连续打开、返回、再打开不同书，确认旧 Future 不覆盖新页面。
9. 修改字号、替换开关、简繁转换和重新分段后重新进入，确认缓存按正确粒度失效。
10. 单章换源、整书换源、删除离线正文和强制刷新后确认不会显示旧正文。
11. 切换游客/账号后确认处理后正文内存缓存已清理，不出现另一作用域旧页面。
12. Android/iOS 触发内存压力或长时间连续阅读多本书，确认 LRU 有界且页面可重新加载。
13. 开启系统减少动态效果和屏幕阅读器，确认转场降级、先导页内容顺序和“开始阅读”操作可访问。

## 12. 推荐结论

建议执行 P0 和 P1，但分两次交付、两轮真机验收：

- P0 解决“每次进入都有 loading”的直接体验问题；
- P1 让重复进入和启动后继续阅读真正命中处理后正文，而不是只用动画掩盖等待。

显示配置应在 App 首帧后完成 MMKV 初始化与一次兼容迁移，并长期使用同步内存快照。首次先导页应作为
有业务意义的第 0 页，重复进入则不强制展示先导页。MMKV、路由动画、快照复用、并行初始化和有界 LRU
缺一项，都无法稳定实现“转场结束直接阅读”。
