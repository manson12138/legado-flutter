# 非强制登录与游客模式实施方案

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`。

本文基于 2026-07-27 的现有 Flutter 代码和认证、用户数据隔离设计梳理并完成实施；未运行编译、测试、分析、格式化或应用。

## 1. 用户目标

- App 不再强制登录，首次安装、没有会话或登录失效时可以直接使用主要阅读功能。
- 登录入口放在“我的”页面顶部右侧。
- 未登录点击该入口进入现有登录/注册页面。
- 已登录点击该入口继续进入现有账号资料、权限、邀请码和退出登录页面。
- 登录后的书架、历史、搜索历史、下载、书源同步和启动后台逻辑继续使用当前账号语义。

本方案把“我的页面顶部右侧”解释为 `AppBar.actions` 中的账号按钮；原资料区右侧的重复账号按钮移除。

## 2. 当前阻塞点

当前不能只删除根部登录遮罩：

1. `_AppStartupGate` 在 `session == null` 时直接渲染不可返回的嵌入式 `AuthenticationRoute`，未登录看不到业务 Navigator。
2. `CurrentUserScope.requireUserId()` 在未登录时抛出异常；书架、目录、分组、阅读历史、搜索历史、下载和启动自动目录更新都依赖它。
3. 默认书源导入、下载恢复、本地书架/历史预加载和启动自动更新目前只在认证会话建立后启动。
4. 远端书源同步、权限、邀请码和部分分析上报确实需要 Token，不能用伪账号或空 Token 模拟登录。

因此需要同时调整启动门、游客本地作用域、后台服务触发和“我的”页入口。

## 3. 推荐的数据策略

### 3.1 本机游客作用域

在 `CurrentUserScope` 中增加保留的本地游客 ID：

```text
guestUserId = -1
```

服务端账号 ID 继续使用服务端返回的正整数。游客 ID 只用于本机 SQLite 复合键和搜索历史缓存键，绝不发送到服务器，也不构造 `AppAuthenticationSession` 或 Token。

现有 Schema v9 的 `userId INTEGER NOT NULL` 没有正数约束，可以直接容纳保留负数，不新增列、不改表、不升级 `LegadoDatabase.schemaVersion` 和 `pubspec.yaml` build number。

### 3.2 隔离规则

| 状态 | 本地作用域 | 用户看到的数据 |
|---|---:|---|
| 未登录 | `-1` | 本机游客书架、历史、搜索历史、进度和下载 |
| 登录 A | A 的服务端账号 ID | A 在本机的独立数据 |
| 登录 B | B 的服务端账号 ID | B 在本机的独立数据 |
| 退出登录 | `-1` | 恢复此前游客数据 |

推荐不自动把游客数据迁移到账号。自动合并会产生同 URL、同名不同源、分组位值、阅读进度和下载任务冲突，也会在用户未明确同意时改变数据归属。后续如有需要，应单独提供“把游客书架导入当前账号”的显式功能。

## 4. 启动和会话流程

```text
App 冷启动
  -> 展示现有最短启动页
  -> 尝试恢复安全会话
     -> 恢复成功：切换到账号 userId
     -> 无会话/已失效：保持 guestUserId=-1
  -> 移除启动遮罩，始终展示业务主界面
  -> 为当前本地作用域启动：
       默认书源初始化
       下载恢复
       书架/历史本地预加载
       书架/历史目录后台自动更新
  -> 只有已登录会话继续启动：
       App 账号准入/权限逻辑
       远端书源同步与待发送分析刷新
```

会话恢复仍应在业务界面显示前完成，避免先展示游客数据、随后又突然切换成账号数据。无会话不再进入认证表单，也不再执行认证输入就绪门控。

登录、退出或会话失效时继续使用 `CurrentUserScope.generation`、带作用域 key 的 `MaterialApp` 和现有取消机制：

- 游客登录成功：取消游客预加载、目录更新和下载运行，切换账号作用域并重建业务树。
- 账号退出或失效：取消账号任务，切回游客作用域并重建业务树。
- 登录成功或退出后，认证路由随根业务树重建而关闭；页面回到当前实现的主入口，不在旧账号页面上继续运行。

## 5. 游客可用能力

游客允许使用：

- 本地书源导入、编辑、启停和普通规则搜索；
- 书籍详情、目录刷新、加入游客书架；
- 游客阅读历史、阅读进度、书签、标注和阅读设置；
- 本地书导入、离线下载和下载管理；
- 启动自动更新游客书架与历史目录；
- 主题、语言、本地日志、关于等设备级能力。

必须保持登录限制：

- 远端书源云同步；
- App 账号权限刷新、邀请码生成和账号资料；
- 任何明确要求 Access Token 的服务端写入；
- 账号级数据的跨设备恢复（当前服务端本来也没有书架/历史同步 API）。

需要登录的入口在游客状态下应展示“登录后使用”，点击后跳转认证页，不能发送空 Token 后再展示网络错误。

## 6. “我的”页交互

### 游客状态

- 标题仍为“我的”。
- 顶部右侧显示登录/账号图标，Tooltip 为“登录或注册”。
- 资料区显示“游客”与“数据保存在本机，登录后使用独立账号数据”。
- 点击顶部按钮进入现有 `AppRoute.authentication`，默认显示登录表单并可切换注册。

### 已登录状态

- 顶部右侧显示账号管理图标，Tooltip 为“账号管理”。
- 资料区显示当前用户名。
- 点击后进入当前账号资料页面，保留权限刷新、邀请码和退出登录逻辑。
- 退出后回到游客主界面，游客数据重新可见。

登录和注册页继续复用现有键盘、焦点、RSA-OAEP 密码加密、安全会话存储和错误脱敏实现，不复制一套新表单。

## 7. 实施范围

| 文件 | 主要改动 |
|---|---|
| `lib/src/app/current_user_scope.dart` | 增加游客保留 ID；未登录时返回游客作用域，账号切换仍递增代次 |
| `lib/src/app/legado_app.dart` | 根门只负责启动会话恢复，不再用认证页覆盖业务树；按游客或账号作用域启动本地后台服务 |
| `lib/src/app/bookshelf_history_startup_preloader.dart` | 沿用当前作用域，不再把未登录视为非法调用 |
| `lib/src/app/bookshelf_history_auto_refresh_service.dart` | 游客作用域下也可更新本地书架和历史目录 |
| `lib/src/model/reader/download_coordinator.dart` | 继续按作用域隔离，游客与账号切换时取消旧运行 |
| `lib/src/ui/settings/settings_route.dart` | 监听会话并把统一认证入口传给“我的”页 |
| `lib/src/ui/settings/settings_screen.dart` | 在 AppBar 顶部右侧显示登录/账号入口，调整游客资料文案并移除重复按钮 |
| `lib/src/ui/authentication/authentication_route.dart` | 只作为普通可返回路由；登录、退出后的根作用域切换关闭旧路由 |
| 认证与用户隔离文档、`AI_PROJECT_INDEX.md` | 更新强制登录结论、游客数据归属和验收状态 |

Repository、DAO 和数据库表无需为游客增加另一套实现；它们继续接收整数 `userId`，避免重复查询分支和额外常驻缓存。

## 8. 性能、内存与安全

- 启动仍只执行一次会话恢复；没有会话时不请求登录接口，不加载认证表单和输入控制器。
- 游客与账号切换继续通过根 key 销毁旧页面、流订阅、网络取消令牌和 ViewModel，避免内存泄漏和跨作用域回写。
- 本地首快照、目录自动更新和下载保持现有有界并发；不会因为游客模式复制 worker。
- 游客 ID 不进入网络请求、日志、埋点或崩溃报告；日志只记录 `guest/authenticated` 状态，不记录账号 ID。
- 不创建伪 Token、不把游客包装成服务端账号、不绕过服务端权限检查。

## 9. 用户验收

1. 首次安装且没有账号时，启动页结束后直接进入主界面，不出现登录页。
2. 游客可导入书源、搜索、加入书架、阅读、保存历史和下载，重启后游客数据保留。
3. “我的”顶部右侧未登录时显示登录入口，点击进入登录/注册；系统返回可回到“我的”。
4. 游客登录 A 后只显示 A 的本地书架和历史，不自动混入游客数据。
5. 已登录时顶部入口进入现有账号管理；退出后恢复此前游客书架、历史和进度。
6. A、B、游客连续快速切换时，不闪现或写入其他作用域的数据，旧下载和自动目录更新被取消。
7. 游客访问远端同步、邀请码等账号能力时先提示登录，不发送空 Token 请求。
8. 有效会话冷启动直接进入账号数据；过期会话安全降级为游客，不强制展示登录页。
9. Android、iOS 分别验证启动、返回键、登录键盘、根路由重建和后台任务释放。
