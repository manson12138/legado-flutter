# 按登录用户隔离本地书架与阅读历史设计

状态：`IMPLEMENTED_PENDING_USER_VERIFICATION / 代码已写入，等待用户运行验收`。本文基于 2026-07-25 的静态梳理与实施，并于 2026-07-27 增加独立游客作用域；未运行编译、测试、分析、格式化或应用。

## 1. 目标与当前差异

目标：同一台设备上，书架、书架分组、阅读历史及其阅读进度必须只属于当前登录用户。切换账号后只能看到目标账号自己的数据；重新登录原账号后恢复其本地数据。

实施前的 v8 实现不满足该目标：`books`、`book_groups`、`reading_history_books`、`reading_history_chapters` 均没有 `userId`，以 `bookUrl` 或 `groupId` 为全局主键，所有账户共用同一份 SQLite 记录。现有远端 API 仅含认证、书源和 App 配置能力，没有书架/历史同步契约，因此本次只实现“本地按用户隔离”，不宣称跨设备同步。

## 1.1 实施快照

- `LegadoDatabase` 已升至 Schema v9，`pubspec.yaml` build number 已升至 `+7`。新装与升级后的书架、分组、目录、历史和下载附属表均使用 `userId` 复合主键、复合外键及用户前缀排序索引。
- v8 到 v9 按确认方案破坏式删除旧书架外键图后重建，不复制旧记录；书源、认证安全会话和设备级 `caches` 不在删除范围。
- Book、BookGroup、ReadingHistory、Download DAO 的全部查询和写入都显式接收用户 ID；Repository 在每次领域操作入口捕获 `CurrentUserScope.requireUserId()`。未登录时返回只供本机使用的游客 ID `-1`，不会回退到公共空作用域。
- `CurrentUserScope` 已加入切换代次。预加载器按用户单飞并在发布前核对用户与代次；会话变化会清空快照、重建带用户 key 的 `MaterialApp`，从而释放旧页面流订阅和内存状态。
- 下载协调器在账号切换时取消 HTTP 与自动换源运行句柄、停止平台后台保活、重置启动单飞，并用调度代次拒绝旧任务的主要晚到回写。
- 当前仍等待用户执行下方 A/B 账号、v8 升级和双平台验收；服务端没有书架/历史同步 API 的限制保持不变。

## 2. 用户可见行为

| 场景 | 目标行为 |
| --- | --- |
| A 用户登录后加入书架、阅读 | 仅写入 A 的本地书架、分组、历史和进度。 |
| 退出 A、登录 B | B 看到空数据或自己此前的本地数据，绝不看到 A 的数据。 |
| 退出 B、重新登录 A | A 的本地书架、分组、历史和进度恢复。 |
| 未登录 | 使用 `userId=-1` 的独立游客书架、历史、进度和下载，并执行本地预加载。 |
| 新设备登录 A | 本次仍为空；需要服务端书架/历史同步 API 后才能跨设备恢复。 |

## 3. 数据模型与迁移

书架属于一组存在外键关系的数据，不能只给顶层 `books` 加列：

```text
用户 userId
  -> books(userId, bookUrl)
      -> chapters(userId, bookUrl)
      -> download_tasks / download_book_states（如继续保留为书架附属数据）
  -> book_groups(userId, groupId)
  -> reading_history_books(userId, bookUrl)
      -> reading_history_chapters(userId, bookUrl)
```

实施采用用户确认的破坏式升级：SQLite 不能直接修改主键和外键，因此 Schema v9 升级时直接删除现有 `books`、`chapters`、`book_groups`、`reading_history_books`、`reading_history_chapters` 及依赖这些书架主键的下载附属表，再按新复合键结构重建表和索引；不复制任何旧记录。新安装的建表 SQL 同时使用新结构。

这意味着升级前本机已有的书架、分组、目录、阅读历史、阅读进度以及关联离线下载状态会永久删除，无法恢复；首次登录的任何账号都不会认领旧数据。书源、认证会话、远端 App 准入/升级缓存等不在删除范围。

## 4. 运行时作用域

- 应用级 `CurrentUserScope` 只暴露本地作用域 ID，不暴露 Token；未登录使用保留游客 ID `-1`，认证会话变化时切换到账号 ID 或切回游客。
- Book、BookGroup、ReadingHistory DAO/Repository 的所有读写、观察、删除、进度恢复和预加载都要求有效 `userId`，SQL 必须带作用域条件。
- 认证退出时取消当前书架/历史流订阅、清空页面内存快照和启动预加载缓存，避免 A 的异步结果在 B 的页面中回写。
- 登录 B 后重新启动其独立预加载任务；任务生成时携带用户 ID，完成前再次核对当前作用域，过期任务直接丢弃。
- 书源、阅读器偏好、封面缓存、远端 App 准入/升级缓存不在本方案范围内，仍沿用现有设备级语义，除非后续另行指定。

后续用户已单独指定搜索关键字历史也按账号隔离；该独立方案已实施，等待用户验收，见
[`user_scoped_search_history_design.md`](./user_scoped_search_history_design.md)。搜索结果匹配方式等不含查询原文的偏好仍保持设备级。

## 5. 拟修改范围

- `LegadoDatabase`：Schema v9、新装建表与 v8 到 v9 的表重建迁移；`pubspec.yaml` build number 同步递增。
- `data/dao/`、`data/repository/`、Gateway 和 UseCase：为书架、目录、分组、下载附属状态、阅读历史及进度加入用户作用域参数和复合约束。
- `app/`：当前用户作用域、认证会话切换时的预加载失效与重新启动。
- `ui/bookshelf/`、`ui/reader/`、下载管理和书籍详情：使用当前用户作用域后的 Gateway，不在 Widget 直接访问数据库。
- `AI_PROJECT_INDEX`、书架/历史和认证交接文档：更新数据归属、迁移和验收说明。

## 6. 性能、内存与一致性约束

- 使用 `(userId, bookUrl)`、`(userId, groupId)` 和相应排序索引，避免在所有账户数据上扫描后再 Dart 过滤。
- 会话代次或用户 ID 变化时取消流订阅和预加载单飞任务，避免闭包保留旧页面、旧用户快照或数据库结果。
- 书架、章节、下载和历史相关迁移必须保持事务与外键完整性；不能出现 A 的章节被 B 的书架引用。
- 任何业务读写都必须具有明确作用域；游客使用固定 `-1`，账号使用服务端 ID，不能写入空字符串或无归属公共数据。

## 7. 用户验收

1. A 添加两本书并阅读，退出后 B 登录：B 的书架和历史不出现 A 的书。
2. B 添加书并阅读，退出后 A 重新登录：A 只恢复自己的两本书和进度。
3. A/B 连续快速切换，确认页面不闪现另一账号的书，也没有旧异步预加载回写。
4. 从当前 v8 数据库升级：旧书架、分组、目录、阅读历史和关联离线下载状态被清空；首次登录后从空数据开始建立当前账号的独立记录。
5. 书架刷新、加入书架、删除、分组、阅读进度、历史记录和离线下载在 A/B 账户下分别验证。
6. 新设备登录已有账号仍不会自动得到书架/历史；该限制在服务端同步 API 未提供前保持明确可见。
7. 游客添加并阅读书籍后登录 A，确认 A 不出现游客数据；退出 A 后游客书架和进度重新出现。
