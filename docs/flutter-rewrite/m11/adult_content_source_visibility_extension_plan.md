# 成人内容屏蔽词与书源可见性扩展方案

状态：`IN_PROGRESS / 代码已实现，等待用户验证`

最后实施：2026-07-29。代码已写入；未运行编译、测试、分析、格式化或应用启动。

## 1. 本次唯一目标

在“屏蔽成人内容”开启时：

1. 向成人内容屏蔽词库加入 `色色`、`耽美`、`腐`、`18`、`色`、`涩涩`、`脸红`、`绅士`、`淫`。
2. 书源名称或书源分组只要包含任一生效屏蔽词，整条书源就不展示，也不参与搜索、整书换源或单章换源。
3. 保留现有搜索结果过滤：小说名、简介、作者名命中屏蔽词时不展示；当前已有的分类字段过滤也继续保留。
4. 关闭“屏蔽成人内容”后，不执行上述书籍和书源过滤。

这里的“包含”按用户原要求解释为不区分大小写的字面子串匹配，不做分词、完整词或独立标签限制。因此 `腐`、`18`、`色` 会产生较宽的命中范围，例如含“角色”“颜色”或普通数字 `18` 的书源/书籍也可能被屏蔽；这是本次明确要求的预期行为，不自行收窄。

## 2. 明确不包含

- 不删除已经同步或已经保存到数据库的书源，只改变开启屏蔽时的可见性和可执行性。
- 不修改兄弟仓库 `legado-with-MD3` 的 Android 代码或远程词库文件。
- 不改变书源 JSON、远程同步协议、数据库 Schema、路由或平台通道。
- 不移除现有的书源备注关键词判定、固定“成人”分组标签判定和域名黑名单判定。
- 不新增第三方依赖，不增加诊断日志。

## 3. 当前实现事实

### 3.1 关键词与远程规则

- `assets/default_data/adult_keywords.txt` 当前为逐行 Base64 编码，共 72 条；9 个明确新增词均已作为独立词条写入。
- `AdultContentRepository.isAdultBook` 已判定书名、作者、分类和简介。
- `AdultContentRepository.isAdultSource` 已判定书源名称、分组、备注和域名，并保留独立“成人”分组标签规则。
- `RemoteAppBootstrapper` 会把服务端启用的关键词和域名交给 `replaceRemoteRules`；当前缓存中的远端规则会整体替换内置词库。若只修改 asset，成功拉取远端规则后，本次新增词可能不再生效。

### 3.2 书源可见性

当前工作区已有未提交改动，必须在后续实现中保留并继续完善：

- `BookSourceRepository.watchAll` 已在书源管理列表展示前调用统一成人内容判定；被屏蔽书源仍保存在数据库。
- `BookSearchCoordinator.loadEnabledSources` 和搜索启动快照已过滤被屏蔽书源，因此搜索页书源选择、实际多源搜索、整书换源和单章换源可复用同一过滤结果。
- `BookSearchCoordinator` 仍在单书源结果返回后过滤书名、作者、分类和简介，符合“之前的过滤也要保留”。
- 直接书源导入仍保留现有 `blockedAdult` 拒绝计数；服务器同步使用 `filterBlockedSources: false` 完整落库，再在展示和执行入口隐藏。此次不改变两种导入路径的既有差异。

### 3.3 需要补齐的实时性

- 屏蔽开关和远程词库写入 `caches` 表，但书源管理列表当前主要跟随 `book_sources` 表变化。
- 搜索页在创建 ViewModel 时读取一次启用书源，首页 `IndexedStack` 会保留页面状态。
- 因此用户在设置页开启/关闭屏蔽或更新词库后返回保活页面时，书源管理列表、分组入口和搜索书源选择器可能仍显示旧快照，直到页面重建或书源表发生其他变化。
- 若切换开关时搜索仍在运行，旧运行快照中的书源可能继续执行；必须确保切换后的结果和书源列表不再展示已屏蔽来源。

## 4. 行为矩阵

| 场景 | 屏蔽关闭 | 屏蔽开启 |
|---|---|---|
| 小说名命中 | 保留 | 不展示 |
| 作者名命中 | 保留 | 不展示 |
| 简介命中 | 保留 | 不展示 |
| 分类命中 | 保留 | 不展示，延续现有行为 |
| 书源名称命中 | 展示并可执行 | 整条书源不展示、不执行 |
| 书源分组命中 | 展示并可执行 | 整条书源不展示；该书源不再派生分组入口 |
| 书源备注/成人标签/黑名单域名命中 | 延续现有关闭行为 | 延续现有屏蔽行为 |
| 已同步的命中书源 | 数据保留 | 仅隐藏和禁止参与相关搜索 |
| 运行中切换为开启 | 原任务可继续 | 取消或隔离旧搜索结果，刷新可用书源快照 |

## 5. 拟实施方案

### 5.1 词库合并规则

1. 将 9 个新增词按现有格式写入 `assets/default_data/adult_keywords.txt`，仍使用逐行 Base64，不在 asset 中混入明文格式。
2. 把内置词库定义为本地最低屏蔽基线；远程启用关键词在其上做并集扩展，而不是让远端覆盖层移除这 9 个明确要求的本地词。
3. 对解码结果去空白、去空项并去重；匹配保持不区分大小写。
4. `keywordCount` 展示最终实际生效的去重词条数量。

这样可保证离线启动、远程配置成功、手动更新词库和应用重启后，9 个词的行为一致。

### 5.2 统一书源判定

继续只通过 `AdultContentGateway.isAdultSource` 判定书源，不把关键词循环写进 Widget、ViewModel 或各换源页面：

- 书源名称：任一关键词子串命中即屏蔽。
- 书源分组：整个分组原始文本参与关键词子串判定；任一分组片段命中就隐藏整条书源。
- 书源备注、固定成人标签和域名黑名单：原行为不变。
- 屏蔽关闭时使用已有内存开关快路径，直接返回原始书源集合。

### 5.3 所有展示与执行入口

保持并核对以下入口全部使用统一结果：

1. 书源管理列表及其分组筛选入口。
2. 搜索页书源选择器、分组、名称筛选和反选。
3. 多书源搜索实际调度。
4. 整书换源候选搜索。
5. 单章换源候选搜索。
6. 服务器同步后的本地展示。

详情页或阅读器按 URL 读取当前书源的内部能力不直接删除，以免已在阅读中的书籍因策略切换发生数据损坏；新搜索和换源入口不再选择被屏蔽书源。

### 5.4 开关与词库变更后的刷新

为屏蔽开关、远程关键词和域名变更提供轻量规则修订通知：

1. `AdultContentGateway` 暴露只读规则变更流或等价的修订通知。
2. `AdultContentRepository` 仅在开关或最终生效规则真正提交后发出通知。
3. 书源管理观察链收到通知后重新使用数据库完整快照计算可见书源，不删除底层数据。
4. `SearchViewModel` 订阅规则变更，取消或隔离正在运行的旧搜索，重新读取可用书源，并清理已不可见的选择项。
5. ViewModel 在 `dispose` 中取消订阅；应用级 Repository 在依赖生命周期结束时关闭自有通知资源，避免监听泄漏。

若后续实现发现现有数据库变更通知可在不监听全部 `caches` 写入的前提下精确复用，可使用同等语义的现有通知机制；不得让搜索历史、阅读缓存等无关缓存写入反复触发书源全量过滤。

## 6. 性能与内存约束

- 开关、关键词和域名继续使用应用级内存缓存，列表过滤不逐条读取数据库或 asset。
- 词库只在规则变更时解码、去重和规范化；Widget `build()` 中不做 Base64、JSON 或全词库预处理。
- 书源和搜索结果仍使用有界顺序过滤，不为每条记录无界创建 Future。
- 规则变更通知不保存页面对象、`BuildContext` 或书源大列表；页面订阅必须随 ViewModel 释放。
- 不增加数据库表或字段，因此 `LegadoDatabase.schemaVersion` 和 `pubspec.yaml` build number 均不变。

## 10. 实施结果

- 9 个新增词已按现有逐行 Base64 格式加入内置词库。
- 内置关键词已改为不可被远程规则移除的最低基线，远程启用词在其上做并集扩展。
- 书源名称、分组、备注、成人标签和域名继续由统一 Gateway 判定；书源管理、搜索及换源复用同一可见性结果。
- 屏蔽开关或远程规则真正变化后发布单调修订：书源管理观察链重新计算列表，保活搜索页取消旧运行、清空旧结果并刷新书源选择。
- 每次搜索运行独立监听规则修订并在结束时释放，避免规则变化后旧书源快照继续返回结果。
- 未新增数据库字段、路由、依赖或平台代码，Schema 和应用 build number 不变。
