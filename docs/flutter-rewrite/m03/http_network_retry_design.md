# 统一 HTTP 网络重试实施方案

状态：`已实现，待用户验证`  
关联阶段：M3 网络与普通规则

## 目标与范围

为所有经 `UnifiedHttpClient` 发起的 HTTP 请求增加底层网络重试。一次请求最多尝试三次：首次请求失败后等待 5 秒重试；第二次失败后再等待 5 秒进行最后一次重试。调用方和 UI 只会在三次都失败，或请求被取消时收到最终错误。

本方案不改变业务层的成功响应、HTTP 状态处理、Cookie 策略、请求参数或书源规则解析语义。

## 当前调用链

```text
Feature / Remote API / 书源规则
  -> UnifiedHttpClient.execute
  -> DioUnifiedHttpClient
  -> Dio + Cookie Manager + 网络日志拦截器
```

`DioUnifiedHttpClient.execute` 是全部统一 API 的唯一底层入口，重试放在此处即可覆盖远程书源同步、认证、公告、词库、普通书源和 JavaScript 桥接所发出的 HTTP 请求，不在界面或具体业务 API 中重复实现。

## 重试规则

| 项目 | 约定 |
|---|---|
| 最大尝试次数 | 3 次（首次 + 2 次重试） |
| 两次重试间隔 | 固定 5 秒 |
| 可重试错误 | DNS、连接失败、TLS、连接/发送/接收/总超时 |
| 不重试错误 | 用户取消、HTTP 状态、响应解码、参数或规则错误、未知业务异常 |
| UI 可见性 | 重试等待和前两次失败只停留在网络层；仅最终失败向调用方抛出 |
| Cookie | 每次尝试重新应用当前 Cookie；仅成功响应保存 Cookie |
| 取消 | 请求中或 5 秒等待期间被取消时立即停止后续尝试并返回取消错误 |

## 超时与并发语义

连接超时保持为 1 分钟。`totalTimeout` 将明确为“单次尝试总超时”，而非三次尝试的总预算；否则首次尝试达到 1 分钟后会耗尽总预算，无法完成用户要求的两次重试。

重试等待不占用新的 HTTP 连接，也不创建额外 Dio 实例。调用方仍只持有原 `Future` 和原取消令牌，因此不会增加页面生命周期泄漏风险。

## POST/写请求风险

用户要求所有 API 都执行重试，因此 POST、PUT、PATCH、DELETE 也会在网络层按相同规则重试。若服务端已完成写入但响应在网络中丢失，重试可能造成重复提交；现有服务端应依赖请求幂等性、唯一约束或去重键保证安全。此次不擅自按方法排除写请求。

## 计划修改

1. 在 `DioUnifiedHttpClient` 拆出单次请求执行，并用固定三次循环包裹。
2. 按 `HttpFailureKind` 判断是否为可重试网络错误。
3. 为取消令牌实现可中断的 5 秒等待，等待期间不向 UI 抛出中间错误。
4. 在每次请求选项中显式传入 `HttpRequest.connectTimeout`，确保契约配置实际生效。
5. 更新 `HttpRequest.totalTimeout` 的中文注释为单次尝试语义。

## 用户验收

1. 断网或让目标服务连接超时，确认日志中可看到三次网络请求，前两次间隔约 5 秒。
2. 第三次仍失败时，确认界面只显示一次最终失败。
3. 在第一次失败后的等待期取消页面请求，确认不再发起下一次请求。
4. 恢复网络后，确认任一重试成功即可正常返回，界面不显示失败。

不会由 Codex 运行构建、测试、静态分析或网络请求。
